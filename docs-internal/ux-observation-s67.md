## 新規に見つけた課題

### 課題A. モバイルでLessonNavの現在レッスン名が16chで途中省略される

- `.lesson-nav__current` が `max-width: 16ch` + `text-overflow: ellipsis` + `white-space: nowrap` になっており、モバイル（390幅）では長めの節タイトルが必ず打ち切られる
- 実観察: 2-3で「整列とリサイズ挙動…」、3-3で「コード生成を見据…」、4-2で「タスクカードをコンポー…」がいずれも末尾省略
- 効果: 自分がどのレッスンにいるか一瞬わからず、パンくずの役割（現在位置の明示）が半減する。冒頭h1に同じ節タイトルが直後に出るので実害は小さいが、パンくずだけを見た瞬間の把握性が落ちる
- 改善案: モバイルではellipsisを外して2行までwrap許容にするか、章名側を「3章」だけに短縮して現在レッスン名の枠を広げる

### 課題B. ゴール確認の`code`が `word-break: break-all` で英数トークンの途中改行される

- `.goal-checklist-item code` に `word-break: break-all` が付いており、mobile 4-2のゴール確認で `PriorityTag` が「PriorityTa/g」、`TaskCard` が「TaskCa/rd」のように途中で改行される
- 原因: S65で6-2の`<code>`長トークン（例 `TaskList.tsx`）が横スクロールを引き起こしたのを潰すために `break-all` を入れた副作用。短い識別子まで無条件に途中で折り返す
- 効果: 「PriorityTag」というトークン名を「PriorityTa」と「g」に分けて読む必要があり読解性が落ちる。トークン単体が短くて改行しなくても入る幅なのに割ってしまう
- 改善案: `word-break: break-all` を外し、`overflow-wrap: anywhere` 単独に戻す。anywhereは「他に改行機会がないときだけ任意位置で割る」挙動なので、長すぎるトークンだけを割り短いトークンは温存できる

### 課題C. レッスン一覧ページ配下のフッター「次のページ」が常に1-1を指す

- `/lessons/` を開いたときフッター前後リンクは「次のページ: 1-1 画面構成を知る」だけが出る
- 効果: レッスン一覧は復習者が任意のレッスンにジャンプする起点なのに、フッターは冒頭から順に読む線形読者しか想定していない。任意ジャンプ後にトップへ戻る導線もなく、ページ末で行き止まり感が出る
- 改善案: レッスン一覧ではフッターの前後リンクを非表示にするか、フッターに「トップに戻る」など主導線を置く

### 課題D. トップの学習時間表とふきかえの日数感が2箇所で言及される

- `## 学習時間の目安`表で「Day1 約2.5時間 / Day2 約2時間 / 全体 約4.5時間」を出したあと、その下の段落で「業務の隙間で進めるなら10〜15日ほどで消化するイメージ」と再度日数の目安を提示
- 効果: 前後で「約4.5時間で終わる」と「10〜15日かかる」が並び、読者が「結局どっちなの」と迷う。読み進めの実時間とハンズオン込みの実時間を区別している趣旨は文中にあるが、表と直下段落で温度差が出る
- 改善案: 段落側の10〜15日は表のキャプションに繰り込むか、「Figmaで手を動かす時間を含めるとこの2〜3倍」など倍率で言い切って数字の重複表示を避ける

### 課題E. トップのカリキュラム表からは各章の2本目以降のレッスンに直接飛べない

- カリキュラム表のリンクは1章あたり先頭レッスン1本のみ（1-1 / 2-1 / 3-1 / 4-1 / 5-1 / 6-1 / 7-1）
- レッスン一覧経由なら1クリックで済むが、初訪問者が「2章の中身を先に見たい」と思ったときトップの表を見ても2-2や2-3にはトップから直行できない
- 効果: `/lessons/` に一度飛べば解決するが、トップ→表→レッスン一覧→2-2 と3クリック必要になり、表からの直接遷移期待を裏切る
- 改善案: 表の`内容`セルにレッスン一覧ページのアンカー（例 `/lessons/#day1`）へのリンクを1本足す、または表内容セル自体に個別レッスンリンクを追記する

### 課題F. 2-2 58行目の「2-1で描いた下地の四角形はもう不要」が代替手順と噛み合わない

- 33行目に「手元にない場合は正円1つとテキスト2つを置いてから始めてください」と代替を案内している一方、58行目では「2-1で描いた下地の四角形はもう不要です。削除して構いません」と再び2-1文脈で書かれている
- 効果: 代替手順で始めた復習者には「下地の四角形」がそもそも存在しないので削除指示が空振り。読み飛ばせば実害ないが、CLAUDE.mdの単体完結ルール（1-3章）に対する例外の残存
- 改善案: 「下地の四角形があれば削除、なければそのまま」と条件句にする、または「不要になった下地は消しておきます」と主語をぼかす

## 副作用の確認

- LessonNavが非レッスンページに漏れていないか: `/`（トップ）と`/lessons/`で描画0件。ロジック（`page.relativePath` を `lessons/\d+-\d+/` にマッチ）が意図通り機能
- GoalChecklistが対象h2が無いページで暴発しないか: 該当なし。ページ遷移後の再実行も `dataset.goalChecklistEnhanced` フラグで二重処理を回避している
- 進捗の永続化: 1-1で1件チェック→リロード後も1件チェック状態を維持。localStorageキー `goal-checklist:v1:/lessons/1-1/` で保存されており動作OK
- 横スクロール（S65修正の副作用）: `/`, `/lessons/`, `1-1`, `2-2`, `2-3`, `3-3`, `4-2`, `6-2`, `6-3` のデスクトップ・モバイルすべてで`scrollWidth == clientWidth`。修正が本ラウンド範囲で再発していない
- 副作用として **課題B**（`word-break: break-all` によるトークン途中改行）と **課題A**（`max-width: 16ch` のellipsis切り詰め）を新規発生させている

## 総合所見

第1ラウンドで指摘した3大ボトルネックは、初訪問者向け情報の不足、章切れ目/進捗/パンくず不在、復習者導線がサイドバー頼み、のいずれも骨格レベルで解消できている。特にLessonNav（進捗+パンくず）とGoalChecklist（永続化つきチェックUI）と`/lessons/`一覧の導入は、初訪問者・受講者・復習者いずれのペルソナでも到達性と現在位置把握を明確に上げている。

一方で、改善実装そのものが細部で新しい摩擦を生んでいる。特にモバイル固有の摩擦が2件（LessonNavの16ch省略、`code`のbreak-all）は、S65のモバイル横スクロール修正とセットで導入された配慮が過剰に効いた結果で、狭幅時のリーダビリティを下げている。次スプリントはこの副作用の解消を最優先にすべき。

コンテンツ側では、CLAUDE.mdの二層化（1-3章=単体完結、4-6章=連続構築）は妥当だが、既存レッスンへの反映は33行目の代替追加までで、58行目のような残余は取り切れていない。二層ルールを既存レッスン全体に一度通しで適用する棚卸しがあると整合が取れる。
