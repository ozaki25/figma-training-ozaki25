# 4章・5章 再設計案（v3 完成形の情報密度を確保する版）

作成日: 2026-07-04

## 何を直すのか

現状の完成形は `task-list` / `task-form` ともに Desktop 1440×1024 フレームでありながら、
実質的に使っている領域は上から 300px 前後（ヘッダー64 + 見出し + カード3〜4枚 or フォームカード）
に留まる。1440×1024 の面積のうち**約28〜32%**しか埋まっておらず、下 700px 弱が空白の灰色。
受講者が完成画面を見ても「タスク管理ツールっぽくない」「これ作った、と言えない」。

学習項目（4-1〜5-3）は変えずに、**完成形の見た目だけをアプリらしい情報密度に引き上げる**のが本設計の目的。

## 前提: 学習項目は不変

| レッスン | 学ぶこと（不変） |
| --- | --- |
| 4-1 | フレーム・Auto Layout・Fill/Hug で骨組み |
| 4-2 | コンポーネント化とインスタンスの並び |
| 4-3 | 色スタイル・テキストスタイル |
| 5-1 | 別画面の骨組み（4章手順の再利用） |
| 5-2 | 別コンポーネント（TextField / Button）、バリアント |
| 5-3 | 2画面の一貫性チェック |

3章のプロフィールカードと6章の指示雛形は据え置き。変えるのは4章・5章の**題材の仕様**だけ。

## 完成形の全体像

2画面とも「左サイドバー + 右コンテンツ」の**2カラム構成**にする。これでDesktop幅1440を使い切る。

```
[task-list]                                [task-form]
┌──────┬──────────────────┐   ┌──────┬──────────────────┐
│      │ header 64        │   │      │ header 64        │
│side  ├──────────────────┤   │side  ├──────────────────┤
│bar   │ page-title       │   │bar   │ page-title       │
│240   │ stat-row (3枚)   │   │240   │                  │
│      │ filter-bar       │   │      │  form-card 560   │
│(共通)│ section: Today   │   │(共通)│  ┌────────────┐  │
│      │  TaskCard ×3     │   │      │  │TextField×5 │  │
│      │ section: This W. │   │      │  │Button×2   │  │
│      │  TaskCard ×3     │   │      │  └────────────┘  │
│      │ section: Later   │   │      │                  │
│      │  TaskCard ×2     │   │      │                  │
└──────┴──────────────────┘   └──────┴──────────────────┘
1440 × 1024                    1440 × 1024
```

面積の使用率見積り（改善後）:

- task-list: サイドバー240×1024 + 右カラム(1200×1024の中身がheader64 + content実描画950以上)
  = **実描画エリアがフレームの95%以上**を埋める。空白は右下わずか。
- task-form: 同じサイドバー + フォームカード(560×約720)を上中央配置 + 上下に控えめな余白
  = 描画されるピクセルは60〜65%だが、**サイドバーとヘッダーで枠が締まるので視覚的にはアプリとして完成**して見える。

## レッスン別 追加/変更の要点

### 4-1 レイアウトの骨組みを作る

**変更点**: 2階層 → **3階層（sidebar + main）に拡張**。

追加で扱うこと:
- 一番外側を**横Auto Layout**にする（現状は縦のみ）
- サイドバーは**幅Fixed 240**、mainは幅Fill → 「横方向のFixed+Fill」は初出だが、2-3の学習の応用として自然
- サイドバーの中身は**シンプルなプレースホルダー段階では"nav-itemの空フレーム5個"だけ**にして、細かい装飾（アイコン・ユーザーブロック）は4-3の仕上げに回す。4-1は骨組みに集中

**演習ステップ**（改訂）:
1. `task-list` 1440×1024、横Auto Layout
2. `sidebar` 240×Fill、縦Auto Layout、白背景、padding 24、gap 8。中に "App" の仮テキスト + 高さ32のプレースホルダー5個
3. `main` 幅Fill×高さFill、縦Auto Layout
4. `header` 64高さ、幅Fill を main に入れる
5. `content` 幅Fill×高さFill、gap 24、padding 32、`#F5F5F5` を main に入れる
6. contentに `page-title` "今日のタスク" と仮の四角形3個

**時間見積り**: 20分弱。従来15分→やや延びる。1つずつの手順は既習なので延びても許容。

### 4-2 タスクカードをコンポーネント化して並べる

**変更点**: TaskCardの中身要素が3個→6個に増える。

新出概念は**なし**（すべて既習の要素の組み合わせ）。ただし:
- TaskCard内部で**縦Auto Layout（task-body）を横Auto Layoutにネスト**する場面が初出。3-2でプロフィールカードのavatar+テキスト縦積みで練習済みなので接続はスムーズ
- `PriorityTag` を**別コンポーネントとしてサブに作る**（1つのレッスンで2コンポーネント）。学習項目「コンポーネント化とインスタンス」の**繰り返し**になり、むしろ理解が深まる

**演習ステップ**（改訂）:
1. PriorityTag（padding 4/8、角丸4、テキスト12 Medium）を1枚作ってコンポーネント化
2. TaskCard を1枚組む（checkbox + PriorityTagインスタンス + task-body(縦gap4のtitle+desc) + CategoryBadgeフレーム + assignee円 + task-due）
3. TaskCardをコンポーネント化、レイヤー名を規約通りに
4. 仮placeholderを消し、TaskCardインスタンスを content に3枚並べる（sectionは4-3で導入。ここでは平置き）
5. 各インスタンスのタイトル・説明・期限・担当・カテゴリ・PriorityTagの色を上書き

**時間見積り**: 25分。長い場合は「PriorityTagを作る」を独立ミニタスク扱いにしてもよい。ただしレッスン分割はしない（学習項目を変えない縛りのため）。

### 4-3 配色・タイポグラフィを仕上げて完成させる

**変更点**: スタイル数が微増（色5→7、テキスト4→5）。ここで初めて**セクション分け**と**stat-row / filter-bar / サイドバー詳細**を仕上げる。

**演習ステップ**（改訂）:
1. 色スタイル7個・テキストスタイル5個を登録
2. 既存要素にスタイルを適用（header、page-title、TaskCard中身）
3. `stat-row` を作る（StatCardの雛形を1枚作って複製3枚、中身を "今日8/完了12/遅延2" で上書き）
4. `filter-bar` にChipを4個並べる（Allだけ紫背景、他は白+枠線）
5. TaskCardの並びを**section-today / section-week / section-later** の3グループに分ける。sectionラベル（14 SemiBold `text/sub`）を各グループの頭に付ける
6. サイドバーの仕上げ: ブランドロゴ・nav-itemに アイコン(20×20の四角プレースホルダーでOK) + ラベル、今日にバッジ、下端にuser-block
7. 完了タスクを1件、チェック紫塗り + タイトル`text/sub` + 打ち消し線

**時間見積り**: 30分。従来15分から倍増するが、**このレッスンが4章の集大成**なので厚くする合理性はある。ペースが読めない場合は「サイドバー装飾」を任意ステップにする逃げ道を残す。

### 5-1 フォームのレイアウトを組む

**変更点**: 骨組みに sidebar を含めるが、**task-listのsidebarをコピペで持ってきて使い回す**方針で時短。

**演習ステップ**:
1. `task-form` 1440×1024、横Auto Layout
2. task-listから `sidebar` フレームを**まるごとコピー**して貼り付け、activeの当たりを「受信箱」に付け替え
3. `main` を作り、header（task-listからコピー）と content を積む
4. content の整列を**上中央**、padding 48
5. `form-header` (24 Bold + サブ 14) と `form-card` (幅Fixed 560) を content に入れる
6. form-card の中に仮のプレースホルダー（TextField相当の枠5個 + ボタン2個）を置く

sidebar/headerコピペで浮いた時間を、form-headerの追加と form-card 幅560への微調整に充てる。**新概念は「横中央寄せ」1つのみ**（従来と同じ）。

### 5-2 入力欄・ボタンを作る

**変更点**: TextFieldインスタンス数が3→5、うち2つを横並びネストで配置。Buttonの**secondaryバリアントを実際に使う**。

**演習ステップ**:
1. TextField をコンポーネント化（現状と同じ）
2. Button primary + secondary の2バリアントを作る（現状と同じ）
3. form-card にTextFieldインスタンスを5個並べる。うち "期限" と "優先度" は**横並び2列のフレーム**の中にネスト（横Auto Layout gap 12、両方幅Fill）
4. "説明" のインスタンスは input高さを 96 に上書き（インスタンス上書きの練習）
5. ボタン行を横Auto Layout（幅Fill、整列右）で作り、secondary "キャンセル"（幅Hug）+ primary "タスクを登録"（幅Hug）を入れる

新出概念:
- 「インスタンスのサブ要素の高さ上書き」（既習: テキスト上書きの応用）
- 「Auto Layoutの入れ子で2カラムのフォーム行を作る」（4-2で経験済み）

secondaryバリアントが本番で使われるので、5-2の学習成果が完成物に反映される。

### 5-3 仕上げ・一貫性チェック

**変更点**: チェック観点に「サイドバー」を追加し4→5観点にする。ただし本質は同じ。

チェック観点:
1. サイドバーの構造と幅（240、コピーがずれていないか、activeだけ違うか）
2. ヘッダー（現状と同じ）
3. 色（`border` `bg-active` を含めて）
4. タイポ（`card-desc` の追加確認）
5. 余白・角丸（form-cardの角丸16、TaskCardの角丸12がそろっているか）

「レイヤー名の最終チェック」は現状のまま維持。

## 6章への影響

指示雛形は基本据え置き。ただし生成コードが有意義になる:

- Header + Sidebar + main の2カラムレイアウト → CSS Grid / Flexbox の実践的な例
- TaskCard 内のネスト構造 → コンポーネント設計として実務的
- Form の 2カラム行 → 実務でよくあるフォームレイアウト
- primary/secondary Button → 実務どおりのボタン設計

**生成後に「なるほどタスク管理ツールっぽいコードが出た」と言えるレベル**になる。

## 既存9フレームの扱い方針

方針: **既存の task-list / task-form は破棄して作り直す**。

理由:
- 骨組みから構造が違う（2階層→3階層、sidebar追加）ので追加要素だけ足すと結局グチャグチャになる
- 既存フレームは3週間分の学習成果ではなく「レッスンをなぞって作ったサンプル」に過ぎない
