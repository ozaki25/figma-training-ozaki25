# 教材デザイン v4: 本番クオリティ再設計

2026-07-24決定。4章以降のタスク管理ツール（TaskFlow）を、実務のデザインファイルと同じ品質基準で作り直す。5章は「ゴールと仕様だけ見て自力で作る」方式に変える。

## 前提

- 受講者は1人1ファイルで作業する（名前衝突の考慮は不要）
- 受講者にはDevシートを付与する。ただしモード（バリアブルの複数値）はファイル所属プランに依存するため使わない設計にする
- バリアブルの作成・エイリアス・塗りへの適用は、無料チーム配下のファイルで動作確認済み（3-4執筆時）

## 品質基準

1. 画面上のすべての色は、バリアブル（トークン）かコンポーネント定義の中の値。受講者がインスタンスに生のカラーコードを打つ場面を作らない
2. すべてのテキストにテキストスタイルを当てる
3. 状態（優先度・完了・アクティブ）はバリアントで表現する。上書きで状態を作らない
4. 繰り返し使う・状態を持つ部品はコンポーネントにする

## 色: バリアブル2層（3-4の仕組みを本番で使う）

コレクションは3-4で作った「コレクション1」を続投し、名前を `tokens` に変える。

### 数値トークン（余白・角丸）

3-4の定義（色・余白・角丸を名前付きの値で管理）を本番でも実践する。数値バリアブルは間隔・パディング・角丸に適用する。

| 名前 | 値 |
| --- | --- |
| `space/4` 〜 `space/48` | 4, 8, 12, 16, 20, 24, 32, 48（名前=px値） |
| `radius/4` `radius/8` `radius/12` `radius/16` `radius/full` | 4, 8, 12, 16, 999 |

- チップとバッジの角丸は固定値をやめて `radius/full`（ピル形状）に整理する
- ロゴの正方形の角丸6は `radius/8` に寄せてスケールに乗せる（見た目の差は無視できる）
- 適用UI（実機キャプチャで確認済み、2026-07-24）
  - 間隔: 入力欄右の「⌄」をクリック → メニューの「バリアブルを適用...」→ 一覧から選ぶ
  - 角の半径: 入力欄右に常時ある六角形アイコンをクリック → 同じ「バリアブルを適用」パネルが開く
  - パネルには自分のtokensコレクションだけでなく、Figma標準ライブラリ（iOS and iPadOS 26等）のバリアブルも一覧に並ぶため、「一覧の先頭は自分のコレクション。見つからなければ検索する」と教材に明記する

## テキストスタイル: 役割ベースの8つ

| スタイル | 指定 | 用途 |
| --- | --- | --- |
| `app-title` | 18 SemiBold | ロゴ、ヘッダーのアプリ名 |
| `page-title` | 24 Bold | 画面見出し（両画面） |
| `section-title` | 14 SemiBold | セクション見出し（今日/今週/あとで） |
| `button-label` | 14 SemiBold | ボタンの文字 |
| `card-title` | 14 Medium | タスク名 |
| `body` | 14 Regular | navラベル、入力文字、フォーム説明、ユーザー名 |
| `caption` | 12 Regular | 説明・期限・ラベル・チップ・バッジ |
| `stat-value` | 28 Bold | 統計カードの数値 |

- 旧 `card-desc`・`card-due` は `caption` に統合する
- 「同じ指定でも意味が違えば別名」の学習ポイントは `section-title` と `button-label`（同じ14 SemiBold）が担う

## コンポーネント

| コンポーネント | バリアント | 備考 |
| --- | --- | --- |
| `PriorityTag` | `priority=high/mid/low` | 各バリアントに priority/* の色。カード側はドロップダウンで切り替え |
| `TaskCard` | `done=false/true` | true: checkboxがbrand塗り、task-titleがtext/sub+打ち消し線。トグル型 |
| `NavItem` | `active=false/true` | true: 背景bg-active+バッジ内蔵。バッジ不要な画面ではインスタンス内Deleteで非表示（3-2既習） |
| `StatCard` | なし | 正式にコンポーネント化（旧「しなくてよい」+PascalCase名の自己矛盾を解消） |
| `TextField` | なし | 現行どおり |
| `Button` | `variant=primary/secondary` | バリアント本番適用の2回目という位置づけに変更 |
| `Chip`（任意課題） | `active=true/false` | NavItemと同型。自力で作る任意課題にする |

## 3章までの成果物のクリーンアップ（手順に含める）

- 4-1の冒頭: 練習の成果物（プロフィールカード一式・土台フレーム）を別ページへ移し、ページ名を `practice` に。本番ページは `task-app` にする
- 4-2（トークンのレッスン）: 3-1で登録した色スタイル3つとテキストスタイル2つを削除する（適用先には色が残る）。3-4のコレクションから練習用の `gray/700`・`gray/400` を削除し、`purple/500`・`brand` は本番トークンとして続投
- バリアブルとスタイルで同名（text/mainなど）が併存すると塗りパネルで紛らわしいため、スタイル削除は必須手順とする

## 4章の再構成（3本 → 4本）

実務と同じく「先にトークンを定義し、それを使って組む」順にする。生値で作って後から張り替える工程を作らない。

1. **4-1 レイアウトの骨組みを作る**: 現行 + practiceページ分離のクリーンアップ
2. **4-2 デザイントークンとスタイルを定義する**: 3-1スタイル削除 → tokensコレクションを2層に育てる（色+数値）→ テキストスタイル8つ登録 → 4-1の骨組みに適用
3. **4-3 タスクカードと優先度バリアント**: PriorityTagをバリアント3種で作る（priority/*トークン使用）→ TaskCard → インスタンス3枚（優先度はドロップダウン切り替え）→ StatCard・filter-bar
4. **4-4 サイドバーと状態を仕上げる**: NavItemコンポーネント（activeバリアント）→ セクション分け8枚 → TaskCardのdoneバリアント → 完成確認

## 5章: 自力挑戦方式

- 5-1・5-2の冒頭に「完成イメージと仕様表だけで、まず自力で作る。詰まったら手順を開く」の案内を置き、詳細手順は折りたたみ（`::: details`）にする
- 仕様表は自力で作れる粒度（コンポーネント構造・バリアント・使うトークン/スタイル・数値）まで書く
- 5-1のactive切り替えはNavItemバリアントの操作に変わる（背景の手動付け替えは廃止）
- 5-3は現行のチェックリスト形式のまま
- 時間切れ・詰まったら即手順に切り替えてよいと明記する

## 見送った案

- バリアブルのモード（ライト/ダーク等）: ファイル所属プランに依存するため使わない。7-1の「扱わなかったこと」に既存記載あり
- 色スタイルがバリアブルを参照する構成: 単色の管理はセマンティックバリアブルの直適用が現行の標準。スタイルで包むのは複合的な塗り（グラデーション等）や過渡期の構成で、この画面には不要。意味のない間接参照を1段増やさない
- Chipの必須コンポーネント化: NavItemと学習内容が重複するため任意課題
