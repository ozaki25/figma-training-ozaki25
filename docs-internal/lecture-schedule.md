# 講義形式タイムテーブル（運用メモ）

教材本文は「自習・1レッスン15分」前提だが、実運用は講義形式（講師が説明・実演 → 受講者が追従 → Q&A）。
このメモはその場合の時間配分の目安。サイトには公開しない内部資料。

## 前提

- 講師が各手順を実演し、受講者が自分のFigmaで追従する形式
- 受講者5名（少人数のため大人数向けの割増は不要）
- 受講者全員にDev席を割り当てる方針（MCPレート制限の回避）
- 休憩は約90分ごとに10分、昼60分
- Day1は午後開始（半日）、Day2は朝からの丸一日。始業時刻は仮にDay1=13:00・Day2=9:30。実際の時刻が決まれば表ごとスライドで対応

## 設計の意図

- **境目は3章と4章の間**。1〜3章は同じサンプル（プロフィールカード）で手順を練習するだけの章なので、半日のDay1に収めやすい。4章以降は本番の2画面制作とコード生成という重い内容なので、丸一日のDay2にまとめて置く
- **Day1は半日で1〜3章がちょうど収まる**。9レッスン・休憩2回で13:00〜18:00の5時間ぴったり
- **Day2が長め（8.5時間）になるのは意図的**。4章4レッスン・5章3レッスン・6章3レッスン・7章1レッスンの計11レッスンを1日に詰め込むため、休憩を多めに挟んでいる
- **6章のMCPが一番事故りやすい**。6-1のセットアップで5人ぶんの環境差が出るので、前後に休憩を厚めに取っている
- **6-2/6-3の前提**: Dev席検証がOKなら各自試行で上記時間。もし検証NG（無料6コール制限）なら、この2つは講師デモ中心に切り替え、各自は1回だけ実行 → 実質20〜25分ずつに短縮され、Day2後半に余裕が出る

- Day2の8.5時間が長すぎる場合、3-4（バリアブル・デザイントークン）をDay2朝イチへ回す案がある。ただし3章の連続性が崩れるデメリットあり
- 実始業時刻が決まれば表を丸ごとスライドするだけで対応可
