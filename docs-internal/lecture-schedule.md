# 講義形式タイムテーブル（運用メモ）

教材本文は「自習・1レッスン15分」前提だが、実運用は講義形式（講師が説明・実演 → 受講者が追従 → Q&A）。
このメモはその場合の時間配分の目安。サイトには公開しない内部資料。

## 前提

- 講師が各手順を実演し、受講者が自分のFigmaで追従する形式
- 受講者5名（少人数のため大人数向けの割増は不要）
- 受講者全員にDev席を割り当てる方針（MCPレート制限の回避）
- 休憩は約90分ごとに10分、昼60分
- 始業時刻は仮に9:30。実際の時刻が決まれば表ごとスライドで対応

## 設計の意図

- **4章はDay1に丸ごと残す**。4-3は章の集大成なので、Day2に切り離すと連続性が崩れる。結果Day1はフル、Day2は軽めだが意図的
- **Day2を軽くした理由**: 6章のMCPが一番事故りやすい。6-1のセットアップで5人ぶんの環境差が出るので、午後と予備40分をバッファに充てる
- **6-2/6-3の前提**: Dev席検証がOKなら各自試行で上記時間。もし検証NG（無料6コール制限）なら、この2つは講師デモ中心に切り替え、各自は1回だけ実行 → 実質20〜25分ずつに短縮され、Day2はさらに余裕が出る

## 事前にやること

- MCPレート制限の検証（Dev席で無料配下ファイルを7回以上叩き、止まらないか確認）。結果しだいで6章の進め方を確定する
- 受講者5名ぶんのDev席を研修時間中まとめて割り当て
- 各受講者のFigmaアカウント作成とファイルへのEdit招待

## 調整の余地

- Day1を軽くしたいなら、4章を翌朝へ回す案もあるが章分断のデメリットあり
- 実始業時刻が決まれば表を丸ごとスライドするだけで対応可
