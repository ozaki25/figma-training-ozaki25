# 講師ノート（運用メモ）

教材本文は自習でも通せるように書いてあるが、講義形式では講師が説明・実演し、受講者が追従する。
このメモは各レッスンで講師が話す内容の要点。台本ではないので、自分の言葉で話す前提で使う。
時間配分は `lecture-schedule.md` を参照。サイトには公開しない内部資料。

各レッスンの項目は次の4つ。

- **話すこと**: 演習の前に口で説明する内容
- **実演すること**: 講師が画面を共有して見せる操作
- **演習前に伝えること**: 受講者が手を動かす前に言っておくと詰まらないこと
- **つまずきポイント**: 実際に手が止まりやすい箇所と、そのときの声かけ

## 1章 Figmaを開いてみる

章のはじめに「1〜3章は練習用のプロフィールカードで操作に慣れる時間で、本番の画面は4章から作る」と言っておく。
練習の題材が本番と関係ないことを先に言わないと、何を作っているのか分からなくなる。

### 1-1 画面構成を知る

**話すこと**

- 画面は4エリア。キャンバス（中央）、ツールバー（下部中央）、左サイドバー、右サイドバー
- エンジニア向けの対応: 左サイドバーはDOMツリー、右サイドバーは開発者ツールのStylesペイン、キャンバスはレンダリング結果
- 右サイドバーは「いま選択しているもの」で中身が変わる。何も選択していないとファイル全体の情報になる
- ツールバーが下部にあるのは2024年の刷新以降。古い記事は上部にあるので混乱しないように

**実演すること**

- `r` で四角形を描き、左サイドバーに `Rectangle 1` が出るところ
- 右サイドバーのX・Y・W・Hを書き換えて、四角形が動く・サイズが変わるところ
- キャンバスの空白をクリックして、右サイドバーの中身が切り替わるところ

**演習前に伝えること**

- 描いたあとに見るのは左サイドバーの行と右サイドバーのプロパティの2か所

**つまずきポイント**

- キャンバスが黒い受講者がいる。Figmaアプリの外観設定がダークだと新規ファイルもその色で始まる。教材のキャプチャと合わせたい人は「ページ」セクションの色を `#F5F5F5` にする（本文のtipに書いてある）
- 最左端の細い縦バー（ナビゲーションバー）が出ている人と出ていない人がいる。進行には影響しないと言っておく

### 1-2 フレームを作って操作する

**話すこと**

- フレームは入れ物、四角形はただの図形。画面を作るときはフレーム
- セクションという入れ物もあるが、このハンズオンでは使わない
- プリセットは「デスクトップ」1440×1024を使う。一覧にはiPhone・iPad・MacBookなど実機サイズが並ぶ

**実演すること**

- `f` → プリセットから「デスクトップ」を選ぶとフレームが置かれるところ
- `Cmd/Ctrl + スクロール` でズーム、`Space + ドラッグ` でパン、`Shift + 1` で全体表示
- ページの追加と切り替え。切り替えてもレイヤーは消えていないこと

**演習前に伝えること**

- 迷子になったら `Shift + 1`。これだけは全員に覚えてもらう

**つまずきポイント**

- パンのつもりでドラッグして要素を動かしてしまう。`Space` を押しながらであることを強調する
- 2つ目のフレームを1つ目の中に作ってしまう。重なると入れ子になるので、離れた場所に置くよう言う

## 2章 基本要素を作る

この章から3章の終わりまで、同じプロフィールカードを引き継ぐ。毎レッスンの冒頭で「前のレッスンで作ったカードを使う」と確認する。

### 2-1 シェイプとテキストを配置する

**話すこと**

- 図形は `r`（四角形）と `o`（楕円）。`Shift` を押しながらドラッグで正方形・正円になる
- 角丸は「外見」の「角の半径」、塗りは「塗り」のスウォッチ。CSSの `border-radius` と `background-color`
- テキストは `t` を押してからキャンバスを**クリック**して入力する。ドラッグで箱を描くと幅が固定になって折り返す。この教材では常にクリックで作る
- レイヤーの重なり順は後から描いたものが手前。左サイドバーの一覧の上にあるものほど手前

**実演すること**

- グレーのフレーム → 白い角丸の四角形 → 正円 → テキスト2つの順に置く
- テキストのウェイトを変える場所（フォント名の下のドロップダウン）
- `]` で最前面、`[` で最背面。白い四角形を手前に出して部品が隠れ、戻すと出てくるところ

**演習前に伝えること**

- 位置は目分量でよい。整列は次のレッスンでやる
- 肩書きのテキストは、直前に作った名前の設定（16 Bold）を引き継いで出てくる。サイズとウェイトを両方直す

**つまずきポイント**

- テキストをドラッグで作ってしまい、あとで折り返しがおかしくなる。作り直しが早い
- 部品をフレームの外に置いてしまう。左サイドバーで入れ子になっているか一緒に確認する

### 2-2 オートレイアウトで並べる

**話すこと**

- 目分量だと要素を1つ足すたびに全部ずらして測り直すことになる
- オートレイアウトは方向・間隔・余白のルールで自動に並べ直す仕組み。flexboxをGUIで操作しているものと考えてよい
- `Shift + A` で包む。この教材では以後ずっとこの言い方をする。解除は `Shift + Option/Alt + A`
- 右サイドバーの「オートレイアウト」セクションで、フロー（`flex-direction`）・間隔（`gap`）・パディング（`padding`）・配置（`align-items`）を調整する

**実演すること**

- 名前と肩書きを選んで `Shift + A` → 間隔4
- それと正円を選んでもう一度 `Shift + A` → フロー横、間隔16、配置は上下中央
- 外側にパディング24、白い塗り、角丸16を付けてカードにする
- 肩書きを `Cmd + D` で複製して、間隔4を保ったまま3行目が入るところ

**演習前に伝えること**

- 外側のフレーム自体がカードになるので、2-1で作った下地の四角形は削除する
- 包んだ瞬間に並び方向はFigmaが推測する。意図と違ったらフローで直せばよい

**つまずきポイント**

- 包む対象を間違える（下地の四角形まで選んでしまう）。選択してから左サイドバーで何が選ばれているか確認させる
- フローが縦横逆になる。推測が外れただけなので直せばよいと伝える
- 配置の9マスが効かないように見える。効くのは余りがある方向だけ（2-3で扱う）

### 2-3 整列とリサイズ挙動（内包/拡大/固定）を理解する

**話すこと**

- オートレイアウトの中では幅・高さを「数値」ではなく「振る舞い」で決める
- 内包は中身が決める（`fit-content`）、固定は自分が決める（`320px`）、拡大は親が決める（`flex: 1`）
- 英語表示や海外記事では Hug / Fixed / Fill。用語の対応だけ伝えておく
- 選べない条件がある。内包はオートレイアウトフレームとテキストだけ、拡大は親がオートレイアウトのときだけ
- 整列が効くのは、その方向に余りがあるときだけ

**実演すること**

- カードの幅を固定320にして右に余りができ、9マスで寄り方が変わるところ
- 拡大を外側のグループ → 中のテキストへ順に当てる。途中が内包だと連鎖が切れることも見せる
- 長い名前を入れて2行に折り返り、カードの幅は320のままであること
- さらに行を増やして、テキストの縦積みが正円より高くなった時点でカードの高さが伸び始めること

**演習前に伝えること**

- 拡大は外側から順に当てる。途中で切れると中のテキストが狭いままになる
- 名前は `あ` の連打でよい。何行必要かは環境で変わるので、伸び始めるまで足す

**つまずきポイント**

- 拡大が選択肢に出てこない。親がオートレイアウトになっていないのが原因
- 高さが伸びないと言われる。正円80×80より高くなるまでは伸びないので、行を足させる
- 元に戻すのを忘れる。名前を短く戻してから3章へ進む

## 3章 デザインの基礎知識

3章は仕組みの章。作る対象は2章のカードのまま変わらず、色・部品・名前・トークンと切り口を変えていく。

### 3-1 カラーとタイポグラフィのルール化

**話すこと**

- その場の感覚で色を選ぶと、微妙に違う紫とグレーが増える。先に決めてそこからだけ選ぶ
- 決める数は少なくてよい。色4つ程度、フォントサイズ4段階程度
- スタイルは決めたルールをFigmaに登録する仕組み。色スタイルとテキストスタイル。定義を1か所変えると全部に反映される
- 4章の本番では色はバリアブルで管理する。ここではスタイルで一括反映の感覚をつかむ

**実演すること**

- 「塗り」セクション右上の4点アイコン → パネル右上の「+」 → 名前を付けて「スタイルの作成」
- 「タイポグラフィ」の4点アイコンから同じ流れでテキストスタイル
- 何も選択していない状態の右サイドバー「スタイル」セクションで、`surface` の色を変えるとカードの背景が変わるところ

**演習前に伝えること**

- 登録するのは色3つ（`surface`・`text/main`・`text/sub`）とテキスト2つ（`name`・`caption`）
- 名前に `/` を入れるとグループになる

**つまずきポイント**

- 4点アイコンが見つからない。セクション見出しの右端にあるので、ホバーして名前が出ることを見せる
- スタイル一覧が出てこない。何も選択していない状態（`Esc`）にする必要がある
- 変更を戻し忘れる。色 `#FFFFFF`、サイズ16に戻して終わる

### 3-2 コンポーネントとバリアントを作る

**話すこと**

- メインコンポーネントが原本、インスタンスが複製。編集できるのは原本だけ
- Reactの `ProfileCard` を定義して `<ProfileCard />` を呼ぶ関係と同じ
- インスタンスで変えられるのは中身の値だけ。構造は変えられない
- 紛らわしい2つ: インスタンス内の `Delete` は非表示になるだけ、「インスタンスの切り離し」でつながりが切れる
- バリアントは1つのコンポーネントに複数の状態を持たせる仕組み。値が `true`/`false` ならトグル、それ以外ならドロップダウンになる

**実演すること**

- `Cmd + Option + K` でコンポーネント化 → アイコンがひし形4つに変わるところ
- インスタンスの名前・肩書きを書き換えても、原本の角丸変更が全部に届くところ
- アバターの正円を `Shift + A` で包む。バッジをアバターに貼り付けるための入れ物
- 「バリアントの追加」→ 2枚目に緑の正円 → 「オートレイアウトを無視」→ 配置の右揃え・下揃え
- プロパティ名を `online`、値を `true`/`false` にして、インスタンス側にトグルが出るところ

**演習前に伝えること**

- カードはグレーの下地フレームの外へ出しておく。インスタンスを並べる場所が必要
- バリアントの値は1枚ずつ選び直して変える。まとめては変えられない
- 操作を間違えたら `Cmd + Z` で戻る。バリアント関連は元に戻せる

**つまずきポイント**

- 包む前にバッジを描いてしまい、カードの直下に置いてバッジがアバターから離れる。アバターを包んだフレームの中に入れる
- バリアントを消したくなったとき: 1枚だけなら選んで `Delete`、コンポーネントに戻したいなら紫の破線枠の外へドラッグ
- バリアントがある状態で `Cmd + D` してもインスタンスにならない（セットの複製になる）。アセットパネルからドラッグするか、既存インスタンスを複製する

### 3-3 コード生成を見据えたレイヤー命名

**話すこと**

- Figmaは「種類 + 連番」で自動命名する。放っておくと `Frame 13` だらけになる。すべての要素を `div` にして `class` を付けていない状態と同じ
- 指針は3つ。役割が分かる名前、英語、形式はチームで統一（この教材は部品はkebab-case、コンポーネントはPascalCase）
- 名前と一緒に構造も見直す。意味のまとまりがフレームになっているか、不要なレイヤーが残っていないか
- 6章のMCPはレイヤー名と構造を手がかりにコードを生成する。ここが生成結果に出る

**実演すること**

- `Cmd + R` でリネーム。複数選択して押すと一括リネームのダイアログが出ること
- テキストレイヤーはリネームすると「入力内容が名前になる」挙動が止まること
- 命名後のレイヤーパネルを上から読んで、構造が説明できる状態を見せる

**演習前に伝えること**

- 付ける名前は本文の表のとおり。`ProfileCard`・`avatar`・`avatar-image`・`user-info`・`user-name`・`user-title`
- バリアントを作ってあるので、紫の破線枠（コンポーネントセット）側も `ProfileCard` にする。緑の正円は `online-badge`

**つまずきポイント**

- どのレイヤーがどれか分からなくなる。レイヤーパネルで選ぶとキャンバス側が青枠で囲まれるので対応を確認させる
- 2枚のバリアントの両方に名前を付ける必要があることに気づかない

### 3-4 バリアブルでデザイントークンを管理する

**話すこと**

- デザイントークンは、色・余白・角丸などの決定に名前を付けて一元管理する考え方
- Figmaではバリアブルが担当する。CSSのカスタムプロパティやTailwindのテーマ設定と同じ発想
- スタイルは複数プロパティの束、バリアブルは単一の値。使い分けは表のとおり
- 2層に分ける。プリミティブ（`purple/500` = `#7C3AED`）とセマンティック（`brand` = `purple/500` への参照）
- CSSでいうと `--purple-500` と `--color-brand: var(--purple-500)` の関係

**実演すること**

- 左端のナビゲーションバーから「バリアブル」を開く
- 「+ 作成」→「色」で1つ目。2つ目以降は追加ボタンがパネル最下部の「+ バリアブルを作成」に変わること
- 値の欄を右クリック →「エイリアスを作成」で `brand` を `purple/500` に向ける
- 四角形に `brand` を当てて、`purple/500` の値を変えると色が変わるところ

**演習前に伝えること**

- 追加ボタンは押すたびに種類の一覧が出る。そのつど「色」を選ぶ
- 名前の欄には `/` より後ろだけが表示される。名前が消えたわけではない
- ここで作る `purple/500` と `brand` は4章でそのまま使う

**つまずきポイント**

- 2つ目を追加するボタンが見つからない。表のすぐ下ではなくパネルの一番下にある
- エイリアスにしたつもりが値を直接入れている。値の欄がカラーコードのままか、参照のチップ表示になっているかで見分ける
- モードの追加でアップグレードのダイアログが出る。プランの範囲外なので閉じて進む（本文のwarningのとおり）

## 4章 実践: タスク一覧画面を作る

Day2の本番パート。冒頭で「1〜3章のプロフィールカードは使わない。ここからタスク管理ツールの画面をゼロから作る」と切り替えを宣言する。
4章は4レッスンで1画面を作り上げる連続作業なので、各レッスンの冒頭で「いまどこまでできていて、これから何を足すか」を言う。

### 4-1 レイアウトの骨組みを作る

**話すこと**

- 作るのは3階層。`task-list` の中に `sidebar` と `main`、`main` の中に `header` と `content`
- 作り方の順序は「中身を作ってから `Shift + A` で包む」。包んだフレームが入れ物になる
- 幅・高さは2-3の内包・固定・拡大で決める。サイドバーは幅固定240、mainは拡大

**実演すること**

- `f` → プリセット「デスクトップ（1440×1024）」→ `Shift + A` で横のオートレイアウト
- サイドバーを中身から作って包み、幅固定240・高さ拡大にする流れ
- `header` の間隔を「自動」にして、アプリ名とアイコンが左右に振り分けられるところ（`justify-content: space-between`）
- `content` に背景を付ける。mainに入れてから塗る

**演習前に伝えること**

- テキストを作ると3-1で登録したスタイルが勝手に当たることがある。切り離しアイコンで外す。止める設定はない
- 面倒なら素のテキストを1つ手元に残して `Cmd + D` で複製して使う

**つまずきポイント**

- キャンバスの背景も薄いグレーなので、`content` をmainに入れる前に塗ると見分けがつかない
- `Shift + A` で包む対象を間違えて階層がずれる。左サイドバーの入れ子を見て直させる
- 幅の拡大が選べない。親がオートレイアウトになっているか確認する

### 4-2 デザイントークンとスタイルを定義する

**話すこと**

- 部品を量産する前に土台を固める。CSSで `--color-brand` や `--spacing-4` を先に定義するのと同じ段取り
- 色は2層（プリミティブ14個・セマンティック15個）、余白と角丸は数値バリアブル13個、文字はテキストスタイル8つ
- 要素に当てるのはセマンティックだけ。プリミティブを直接当てたくなったら、足りないセマンティックがあるサイン
- `radius/full` の999は「常に完全な丸にする」ための慣用値

**実演すること**

- 練習ぶんの片付け（3-1のスタイル5つ、3-4の `gray/700`・`gray/400` を削除、コレクション名を `tokens` に）
- 色を数個追加して見せる。残りは各自で進める作業
- 当て方が3種類あること: 色は4点アイコン、間隔とパディングは入力欄右の「⌄」→「バリアブルを適用...」、角の半径は六角形アイコン
- `space/24` の値を40に変えると、サイドバーとヘッダーのパディング、contentの間隔が一斉に動くところ

**演習前に伝えること**

- ここは登録作業の繰り返し。表を見ながら淡々と進める時間
- 一覧にはFigma標準ライブラリのバリアブルも並ぶ。自分の `tokens` のものを選ぶ。見つからなければ名前で検索

**つまずきポイント**

- 42個の登録で時間差が大きく出る。遅れている人には色のセマンティックまでを優先させ、数値は当てる直前でもよいと伝える
- レイヤー名とスタイル名が同名（`app-title`・`page-title`）で混乱する。当てるのは「タイポグラフィ」のスタイル側
- 練習ぶんの削除を飛ばすと、同名のスタイルとバリアブルが併存して塗りのパネルで区別できなくなる

### 4-3 タスクカードと優先度バリアント（山場）

**話すこと**

- 作るのは `PriorityTag`（3バリアント）と `TaskCard`（6要素）の2つ
- カードは横のオートレイアウト。真ん中の `task-body` だけが自分の中で縦に積む。2-2の入れ子と同じで向きが違うだけ
- `task-body` を拡大にすると余った幅を全部引き受けるので、右の3要素が右端に押し出される
- 優先度は色の上書きではなくバリアント。置いたあとはドロップダウンで切り替わる
- 原本は画面の外に置き、画面にはインスタンスだけを並べる

**実演すること**

- PriorityTagのHighを作ってコンポーネント化 → 「バリアントの追加」2回 → 値を `high`/`mid`/`low` に
- TaskCardを「外で作って中へ入れる」の繰り返しで組む
- 担当者アイコンは正円ではなく角丸のフレームで作ること（正円の図形にはテキストを入れられない）
- `task-body` を拡大にした瞬間に右3要素が右端へ寄るところ
- 原本のパディングを変えると画面の3枚が一斉に変わり、書き換えたタイトルは残るところ

**演習前に伝えること**

- テキストは必ずクリックして作る。ドラッグで作ると折り返して崩れる
- バリアントの値は1枚ずつ選び直して変える
- カードの中の要素はダブルクリックで1階層ずつ入って選ぶ

**つまずきポイント**

- ここが4章で一番時間がかかる。要素の入れ先を間違える人が出るので、レイヤーパネルの並び（左から丸・PriorityTag・task-body・バッジ・アイコン・期限）を見せて確認させる
- PriorityTagのインスタンスをアセットパネルから出せない。3-2で扱ったとおり、セットの複製ではなくアセットパネルからドラッグする
- 原本を画面の中に入れてしまう。外に置くことを繰り返し言う

### 4-4 一覧画面を仕上げて完成させる（集大成）

**話すこと**

- やることは6つ。StatCard、フィルタチップ、NavItem、ロゴとユーザーブロック、セクション分けとカード8枚、doneバリアント
- 操作はすべて既習。新しい考え方はスペーサーだけ
- スペーサー: オートレイアウトでは特定の1か所だけ間隔を空けられない。高さを拡大にした空フレームで余りを吸わせて、ユーザーブロックを下端に押し出す

**実演すること**

- StatCardをコンポーネント化してから複製する流れ（`Cmd + D` なら幅の拡大が引き継がれる）
- NavItemのアクティブ側にバッジを足し、ラベルの幅を拡大にしてバッジが右端に寄るところ
- `spacer` の高さを拡大にした瞬間にユーザーブロックが下端へ動くところ
- doneバリアント: `checkbox` の塗りを `brand`、`task-title` を `text/sub` にして、「タイポグラフィ」の詳細設定（`⋯`）から打ち消し線

**演習前に伝えること**

- カードを増やすのは `Cmd + D` の複製。アセットパネルから出し直すと幅の拡大を当て直すことになる
- 打ち消し線は詳細設定（`⋯`）の中。表に出ていない
- 時間が押していたら、セクション分けとカード8枚（手順5）を先に終わらせ、チップのコンポーネント化（任意課題）は飛ばす

**つまずきポイント**

- 手順が多く、遅れが目立つレッスン。完成イメージのキャプチャを出しておき、どこまで進んだかを自分で照合できるようにする
- 仮置きの四角形5個を消し忘れてNavItemと二重に並ぶ
- `spacer` を空フレームのまま `Shift + A` を忘れて高さの拡大が選べない

## 5章 実践: タスク登録フォームを作る

5章は「自力で作ってみる」構成にしてある（完成イメージと仕様表を先に見せ、手順は折りたたみ）。
講義形式では、まず仕様表を読み上げて各自に着手させ、講師は巡回に回る。全員が止まったところだけ実演する。

### 5-1 フォームのレイアウトを組む

**話すこと**

- サイドバーとヘッダーは4章から**まるごとコピー**する。1から作り直さない
- 構造は4章と同じ3階層。違うのはcontentの中身と配置だけ
- 横中央寄せは2つの設定の組み合わせ。子の幅を固定560で止めて、親 `content` の配置で上段の中央を選ぶ

**実演すること**

- `sidebar` をコピーして `task-form` に貼り、`active` を `今日` から `受信箱` に付け替える
- `受信箱` の中の `badge` を `Delete`（消えたように見えて非表示になるだけ。3-2で扱った挙動）
- form-cardの幅を560で止めた瞬間に画面の横中央へ収まるところ

**演習前に伝えること**

- まず仕様表だけ見て自力で作る。詰まったら折りたたみの手順を開いてよい
- 時間が限られていたら無理せず手順に切り替える

**つまずきポイント**

- `今日` の `active` をオフにし忘れて2つアクティブになる（5-3のチェックでも再登場する）
- 四角形にはパディングや内包を設定できないので、仮ボタンの幅は数値で決める
- コピーしたヘッダーの幅を拡大にし忘れて右端が余る

### 5-2 入力欄・ボタンを作る

**話すこと**

- 作るのは `TextField` と `Button`。Buttonの `variant=primary/secondary` は4章の `priority`・`active`・`done` と同じ作り方
- 入力ボックスは四角形ではなくオートレイアウトフレームで作る。中に文字を入れる必要があるから
- インスタンスには要素を追加できないので、優先度のプルダウンらしさはテキスト（`選択する ▼`）で表現する

**実演すること**

- TextFieldを組んで、外側を固定320にしてから中の `input` を拡大にする（2-3の「外側から順に拡大」）
- Buttonを2バリアントにして、`secondary` を白背景・紫枠・紫文字にする
- `説明` のインスタンスだけ中の `input` の高さを96に上書きして縦長にする
- `期限` と `優先度` を `field-row` にまとめて2列にする

**演習前に伝えること**

- ここも仕様表を見て自力で。詰まったら手順を開く
- インスタンス側で上書きするのは「中身の値」だけ。構造は原本を触る

**つまずきポイント**

- `input` の幅で拡大が選べない。包む前は親がオートレイアウトでないので選べない。順序どおりに進める
- 5個のTextFieldのラベルと例文の書き換えが漏れる。仕様表の並び（`タスク名 *`・`説明`・`期限`・`優先度`・`カテゴリ`）を見せる

### 5-3 仕上げ・一貫性チェック

**話すこと**

- 1画面ずつ見ると整っていても、2つ並べると初めて気づくズレがある
- 見る観点は5つ。サイドバー、ヘッダー、色、タイポ、余白・角丸
- 直し方は3つに切り分ける。トークン未適用、数値違い、部品の不一致
- ここで整えた状態がそのまま6章のコード生成に渡る

**実演すること**

- 2画面を横に並べて `Shift + 1` で俯瞰、`Shift + 2` で片方にズーム
- サイドバーのactiveが両画面で正しいかの確認
- `Cmd + R` の一括リネームで自動命名の残りを直す

**演習前に伝えること**

- サイドバーのactiveの付け替え漏れが一番多い。最初にそこを見る
- 使っていない空フレームと隠しレイヤーは消す。6章の生成結果に出てくる

**つまずきポイント**

- ズレが見つからないと言われる。5観点を上から順に、片方ずつ数値を読んで比べさせる
- 直すつもりでインスタンスを切り離してしまう。原本と同じ値に戻すのが目的だと確認する

## 6章 Figma MCP + Claude Codeでコード化

環境差で事故が出やすい章。6-1は各自の手元の状態がそろうまで進まないので、時間を厚めに取り、先に終わった人には待ち時間が出ることを言っておく。
6-2・6-3の「よくあるやりとり」は想定で書いてある。初回実施で実際に出た症状に差し替える。

### 6-1 Figma MCPサーバーをセットアップする

**話すこと**

- 6章でやるのは、Figmaのデザイン情報をClaude Codeに渡してコードにすること。渡るのは絵ではなく構造（入れ子・オートレイアウト・スタイル・レイヤー名）
- Figma MCPには2つの形（Remote / Desktop）があり、このハンズオンはFigma Desktopアプリが要らないRemoteを使う
- ターミナルは2つ使う。Aはコマンドと開発サーバー、BはClaude Code

**実演すること**

- ターミナルAでコマンド一式を貼って実行し、`task-app` ができるところ
- `npm run dev` → ブラウザで薄いグレーの背景と小さいグレーの文字（Tailwindが効いている合図）
- ターミナルBで `claude` → `/plugin install figma@claude-plugins-official` → 終了して起動し直す
- `/plugin` の Installed タブから認証し、`connected` のバッジが付くところ
- `task-list` のリンクを渡して構造が返ってくるところ

**演習前に伝えること**

- `/plugin` はターミナルのシェルではなくClaude Codeの入力欄に打つ
- 再起動が必要なのは、MCP接続が起動時にしか初期化されないから
- `task-app` の中でClaude Codeを起動しておくと、生成物がこのプロジェクトに書かれる

**つまずきポイント**

- ここが一番事故る。詰まった人には本文のトラブルシューティングの順（プラグインが出てこない → 再起動、connectedにならない → 数秒待って `/plugin` を打ち直す、構造が返らない → リンクとファイルの閲覧権限）を見せる
- リンクのコピーが選択範囲になっていない。`task-list` フレームを選んでから **Copy link to selection**
- 開発サーバーのターミナルを閉じてしまう。Aは起動したままにする

### 6-2 タスク一覧画面をコード生成する（山場）

**話すこと**

- `get_design_context` がフレームの構造・オートレイアウト・トークン・レイヤー名をまとめて取得する。`get_variable_defs` はトークン一覧を返す
- 指示に盛り込むのは4つ。リンク、技術スタック、コンポーネント境界、ファイル配置
- 「レイヤー名を反映してほしい」の1行で、3-3の命名が生成物に残る
- まず読むのはファイルツリー。想定と違えばコードを書き出す前に直せる

**実演すること**

- 雛形のURL行だけ差し替えて投げる
- 返ってきたファイルツリーを読んで、分割が想定どおりか確認する
- 書き出されたあと、ブラウザが自動更新されて画面が出るところ
- 生成コードを4観点（構造・命名・Tailwindクラス・色）で読む

**演習前に伝えること**

- 一発で理想どおりにはならない。追加指示で寄せていく作業だと先に言う
- 同じフレームを何度も読み直させるとツールコールを消費する。最初の指示に情報を盛り込む

**つまずきポイント**

- 生成結果が人によって違うので、講師の画面と一致しない。一致させるものではないと伝える
- 指示のURLを差し替え忘れる
- 生成に時間がかかる。待ち時間に、Figma側の作り込みが生成結果に出るという話（レイヤー名・オートレイアウト・トークン）をする

### 6-3 タスク登録フォームをコード生成する

**話すこと**

- Figmaのバリアントはコード側のpropsにほぼそのまま対応する。5-2で `variant` に `primary`/`secondary` と付けたのがここで効く
- フォーム固有で足すのは2つ。TextFieldとButtonを別ファイルにすること、`variant` をunion型で明示すること
- 頼むのは見た目のコード化まで。イベントハンドラやバリデーションは後から別に指示する

**実演すること**

- 雛形を投げて、`TaskForm.tsx`・`TextField.tsx`・`Button.tsx` の3ファイルに分かれるところ
- `Button.tsx` の `variant` が `'primary' | 'secondary'` になっているかの確認
- 同じ画面にTaskListとTaskFormが縦に並び、色・角丸・フォントがそろっているかを見比べる

**演習前に伝えること**

- 6-2と同じ流れなので、指示の書き方は自分で組み立ててみてよい
- ずれていたら「TaskListと同じTailwind値を使うようにTaskFormを揃えてください」と頼める

**つまずきポイント**

- `variant: string` のような緩い型で出る。union型で書き直させる
- 2画面を見比べる時間が足りなくなる。押していたら3観点（色・角丸/余白・フォント）のうち色だけでもよい
