# 講師ノート（運用メモ）

研修中にちらっと見て「次はここを話す」が分かるように、レッスン順に並べてある。上から順に追えばそのまま進行できる。

演習は各自が本文を読んで進める。講師は巡回とQ&Aに回る。一斉に進めるのは6-1だけ。時間配分は `lecture-schedule.md` を参照。サイトには公開しない内部資料。

**話すこと**は演習の前に口で言う内容。台本ではないので自分の言葉で話す。**見るところ**は巡回中に手が止まりやすい箇所と、そのときの声かけ。

## 1章 Figmaを開いてみる

**章のはじめに**: 1〜3章は練習用のプロフィールカードで操作に慣れる時間。本番の画面は4章から作る。

### 1-1 画面構成を知る

話すこと

- 画面は4エリア。キャンバス（中央）、ツールバー（下部中央）、左サイドバー、右サイドバー
- 左サイドバーはDOMツリー、右サイドバーは開発者ツールのStylesペイン、キャンバスはレンダリング結果
- 右サイドバーは選択しているもので中身が変わる。未選択だとファイル全体の情報
- ツールバーが下部にあるのは2024年の刷新以降。古い記事は上部にある

見るところ

- キャンバスが黒い人がいる。Figmaの外観設定がダークだと新規ファイルもその色で始まる
- 最左端の細い縦バー（ナビゲーションバー）の有無は進行に影響しない

### 1-2 フレームを作って操作する

話すこと

- フレームは入れ物、四角形はただの図形。画面を作るときはフレーム
- セクションという入れ物もあるが、このハンズオンでは使わない
- プリセットは「デスクトップ」1440×1024を使う

見るところ

- 迷子になったら `Shift + 1`。これだけは全員に覚えてもらう
- パンのつもりでドラッグして要素を動かす。`Space` を押しながら
- 2つ目のフレームを1つ目の中に作ってしまう。離れた場所に置かせる

## 2章 基本要素を作る

**章のはじめに**: ここから3章の終わりまで同じカードを引き継ぐ。毎回、前のレッスンの続きから始める。

### 2-1 シェイプとテキストを配置する

話すこと

- 図形は `r`（四角形）と `o`（楕円）。`Shift` を押しながらで正方形・正円
- 角丸は「外見」の角の半径、塗りは「塗り」。CSSの `border-radius` と `background-color`
- テキストは `t` を押してキャンバスを**クリック**。ドラッグで箱を描くと幅が固定になって折り返す
- 重なり順は後から描いたものが手前。`]` で最前面、`[` で最背面

見るところ

- 位置は目分量でよい。整列は2-2でやると伝える
- 肩書きは直前の名前の設定（16 Bold）を引き継ぐ。サイズとウェイトを両方直す
- 部品をフレームの外に置いてしまう。左サイドバーで入れ子を確認させる

### 2-2 オートレイアウトで並べる

話すこと

- 目分量だと要素を1つ足すたびに全部ずらして測り直すことになる
- オートレイアウトは方向・間隔・余白のルールで自動に並べ直す仕組み。flexboxのGUI版
- `Shift + A` でオートレイアウトにする。解除は `Shift + Option/Alt + A`
- 調整するのはフロー（`flex-direction`）・間隔（`gap`）・パディング・配置（`align-items`）

見るところ

- 2-1で作った下地の四角形を削除し忘れる。外側のフレーム自体がカードになる
- オートレイアウトにする対象を間違える（下地の四角形まで選ぶ）
- フローが縦横逆になる。Figmaの推測が外れただけなので直せばよい

### 2-3 整列とリサイズ挙動を理解する

話すこと

- 幅・高さは「数値」ではなく「振る舞い」で決める
- 内包は中身が決める（`fit-content`）、固定は自分が決める（`320px`）、拡大は親が決める（`flex: 1`）
- 英語表示や海外記事では Hug / Fixed / Fill
- 内包が選べるのはオートレイアウトフレームとテキストだけ、拡大は親がオートレイアウトのときだけ
- 整列が効くのは、その方向に余りがあるときだけ

見るところ

- 拡大は外側から順に当てる。途中が内包だと連鎖が切れる
- 拡大が選択肢に出ない。親がオートレイアウトになっていない
- 高さが伸びないという声。正円80×80より高くなるまでは伸びない
- 名前を短く戻してから3章へ進ませる

## 3章 デザインの基礎知識

**章のはじめに**: 作る対象はカードのまま。色・部品・名前・トークンと切り口だけが変わる。

### 3-1 カラーとタイポグラフィのルール化

話すこと

- その場の感覚で選ぶと、微妙に違う紫とグレーが増える。先に決めてそこからだけ選ぶ
- 決める数は少なくてよい。色4つ程度、フォントサイズ4段階程度
- スタイルは決めたルールをFigmaに登録する仕組み。定義を1か所変えると全部に反映される
- 4章の本番では色はバリアブルで管理する。ここは一括反映の感覚をつかむだけ

見るところ

- 4点アイコンが見つからない。セクション見出しの右端にある
- スタイル一覧が出ない。何も選択していない状態（`Esc`）が必要
- 変更を戻し忘れる。色 `#FFFFFF`、サイズ16に戻して終わる

### 3-2 コンポーネントとバリアントを作る

話すこと

- メインコンポーネントが原本、インスタンスが複製。編集できるのは原本だけ
- Reactで `ProfileCard` を定義して `<ProfileCard />` を呼ぶ関係と同じ
- インスタンスで変えられるのは中身の値だけ。構造は変えられない
- 紛らわしい2つ。インスタンス内の `Delete` は非表示になるだけ、「切り離し」でつながりが切れる
- バリアントは1つのコンポーネントに複数の状態を持たせる仕組み。`true`/`false` ならトグルになる

見るところ

- 手が止まったら `Cmd + Z` で戻れると伝える。バリアント関連は元に戻せる
- バリアントがある状態で `Cmd + D` してもインスタンスにならない（セットの複製になる）。アセットパネルからドラッグする
- **バッジがアバターのフレームに入らない**。キャンバス上のドラッグでは狙った親に入らないので、レイヤーパネルでドラッグさせる（リハーサルで実際に発生）

### 3-3 コード生成を見据えたレイヤー命名

話すこと

- Figmaは「種類 + 連番」で自動命名する。放置すると `Frame 13` だらけになる
- すべての要素を `div` にして `class` を付けていない状態と同じ
- 指針は3つ。役割が分かる名前、英語、形式はチームで統一（部品はkebab-case、コンポーネントはPascalCase）
- 名前と一緒に構造も見直す。意味のまとまりがフレームになっているか
- 6章のMCPはレイヤー名と構造を手がかりに生成する。ここが結果に出る

見るところ

- バリアント2枚の両方に名前を付ける必要があることに気づかない
- どのレイヤーがどれか分からなくなる。レイヤーパネルで選ぶとキャンバスが青枠になる

### 3-4 バリアブルでデザイントークンを管理する

話すこと

- デザイントークンは、色・余白・角丸などの決定に名前を付けて一元管理する考え方
- Figmaではバリアブルが担当する。CSSのカスタムプロパティやTailwindのテーマ設定と同じ発想
- スタイルは複数プロパティの束、バリアブルは単一の値
- 2層に分ける。プリミティブ（`purple/500` = `#7C3AED`）とセマンティック（`brand` は `purple/500` への参照）
- CSSでいうと `--purple-500` と `--color-brand: var(--purple-500)` の関係
- **2層にする理由はここで納得しなくてよい。4-2で42個使うと分かる**

見るところ

- 2つ目を追加するボタンは表の下ではなくパネル最下部
- エイリアスにしたつもりが直値。参照ならチップ表示になる
- 名前の欄には `/` より後ろだけが表示される。消えたわけではない

## 4章 実践: タスク一覧画面を作る

**章のはじめに**: プロフィールカードは使わない。ここからタスク管理ツールの画面をゼロから作る。4レッスンで1画面なので、毎回「いまどこまでできていて、何を足すか」を言う。

### 4-1 レイアウトの骨組みを作る

話すこと

- 作るのは3階層。`task-list` の中に `sidebar` と `main`、`main` の中に `header` と `content`
- 外側から順に作る。親フレームを描いてオートレイアウトとサイズを決めてから、その中に子を作る
- 幅・高さは2-3の内包・固定・拡大で決める。サイドバーは幅固定240、mainは拡大
- レイヤー名は後でまとめて直さず、作ったその場で3-3の規約どおりに付ける

見るところ

- 幅の拡大が選べない。親がオートレイアウトになっていない

### 4-2 デザイントークンとスタイルを定義する

話すこと

- 部品を量産する前に土台を固める。CSSで `--color-brand` を先に定義するのと同じ段取り
- 色は2層（プリミティブ14・セマンティック15）、余白と角丸は数値13、文字はテキストスタイル8
- コレクションを2つに分ける。`primitives` に色の値、`tokens` にセマンティックと数値。混ぜると名前順で交ざり、ピッカーでも見分けられない
- 要素に当てるのはセマンティックだけ。プリミティブを当てたくなったら、足りないセマンティックがあるサイン
- ここは登録作業の繰り返し。表を見ながら淡々と進める時間

見るところ

- **時間差が一番開く**（登録42個）。遅れている人は色のセマンティックまでを優先。数値は当てる直前でよい
- 手順3以降はエージェントに任せてよいと本文に書いてある。ただし**エージェントはFull席のみ**で、Dev席の受講者は使えない。席の種類を先に確認しておく
- 当て方が3種類ある。色は4点アイコン、間隔とパディングは入力欄右の「⌄」、角の半径は六角形アイコン
- 一覧はコレクションごとに分かれる。選ぶのは `tokens` のものだけ

### 4-3 タスクカードと優先度バリアント（山場）

話すこと

- 作るのは `PriorityTag`（3バリアント）と `TaskCard` の2つ
- カードは横のオートレイアウト。真ん中の `task-body` だけが自分の中で縦に積む
- `task-body` を拡大にすると余った幅を全部引き受けて、右の3要素が右端に押し出される
- 優先度は色の上書きではなくバリアント。置いたあとはドロップダウンで切り替わる
- 原本は画面の外に置き、画面にはインスタンスだけを並べる

見るところ

- **4章で一番時間がかかる**。詰まるのは要素の入れ先。レイヤーパネルの並び（左から丸・PriorityTag・task-body・バッジ・アイコン・期限）と見比べさせる
- 担当者アイコンは正円ではなく角丸フレーム。正円の図形にはテキストを入れられない
- 原本を画面の中に入れてしまう

### 4-4 一覧画面を仕上げて完成させる（集大成）

話すこと

- やることは6つ。StatCard、フィルタチップ、NavItem、ロゴとユーザーブロック、セクション分けとカード8枚、doneバリアント
- 操作はすべて既習。新しい考え方はスペーサーだけ
- スペーサーは、高さを拡大にした空フレームで余りを吸わせて、ユーザーブロックを下端に押し出す仕組み

見るところ

- 手順が多く遅れが目立つ。押していたらセクション分けとカード8枚（手順5）を先に終わらせ、チップのコンポーネント化（任意課題）は飛ばす
- カードを増やすのは `Cmd + D`。アセットパネルから出し直すと幅の拡大を当て直すことになる
- 打ち消し線は「タイポグラフィ」の詳細設定（`⋯`）の中。表に出ていない
- 仮置きの四角形5個を消し忘れてNavItemと二重に並ぶ

## 5章 実践: タスク登録フォームを作る

**章のはじめに**: 本文は手順を折りたたんである。まず仕様表だけ見て自力で、詰まったら開く。手順が隠れているぶん巡回の比重が上がるので、全員が止まった箇所だけ前で実演する。

### 5-1 フォームのレイアウトを組む

話すこと

- サイドバーとヘッダーは4章から**まるごとコピー**する。1から作り直さない
- 構造は4章と同じ3階層。違うのはcontentの中身と配置だけ
- 横中央寄せは2つの設定の組み合わせ。子の幅を固定560で止めて、親 `content` の配置で上段の中央を選ぶ

見るところ

- `今日` の `active` をオフにし忘れて2つアクティブになる
- コピーしたヘッダーの幅を拡大にし忘れて右端が余る
- 四角形にはパディングや内包を設定できない。仮ボタンの幅は数値で決める

### 5-2 入力欄・ボタンを作る

話すこと

- 作るのは `TextField` と `Button`。`variant=primary/secondary` は4章のバリアントと同じ作り方
- 入力ボックスは四角形ではなくオートレイアウトフレーム。中に文字を入れる必要があるから
- インスタンスには要素を追加できないので、プルダウンらしさはテキスト（`選択する ▼`）で表現する

見るところ

- `input` の幅で拡大が選べない。`TextField` にまとめる前は親がオートレイアウトでない。外側から順に
- 5個のTextFieldのラベルと例文の書き換えが漏れる

### 5-3 仕上げ・一貫性チェック

話すこと

- 1画面ずつ見ると整っていても、2つ並べると初めて気づくズレがある
- 見る観点は5つ。サイドバー、ヘッダー、色、タイポ、余白・角丸
- 直し方は3つに切り分ける。トークン未適用、数値違い、部品の不一致
- ここで整えた状態がそのまま6章のコード生成に渡る

見るところ

- **サイドバーのactiveの付け替え漏れが一番多い**。最初にそこを見る
- ズレが見つからないという声。5観点を上から順に、片方ずつ数値を読んで比べさせる
- 直すつもりでインスタンスを切り離してしまう

## 6章 Figma MCP + Claude Codeでコード化

**章のはじめに**: 渡るのは絵ではなく構造（入れ子・オートレイアウト・トークン・レイヤー名）。ここは言い切るだけでよく、納得するのは6-2で生成物を見たとき。

### 6-1 Figma MCPサーバーをセットアップする

**ここだけ一斉に進める。** 読解ではなく各自の環境の問題なので、自主進行にすると詰まった人が6-2・6-3に進めない。2日間の締めが消える。

話すこと

- Figma MCPには2つの形（Remote / Desktop）があり、Figma Desktopアプリが要らないRemoteを使う
- ターミナルは2つ使う。Aはコマンドと開発サーバー、BはClaude Code
- 再起動が必要なのは、MCP接続が起動時にしか初期化されないから

見るところ

- **全員のプラグインに `connected` が付くまで次へ進まない**。先に終わった人には待ち時間が出ると先に言う
- `/plugin` はターミナルのシェルではなくClaude Codeの入力欄に打つ
- 開発サーバーを動かしているターミナルAは閉じずに起動したままにする
- リンクのコピーは `task-list` フレームを選んでから Copy link to selection
- 詰まった人には本文のトラブルシューティングを上から順に当てる

事前に済ませておくこと: 受講者5名ぶんのDev席割り当て、Figmaアカウント作成とファイルへのEdit招待、MCPレート制限の検証。

### 6-2 タスク一覧画面をコード生成する（山場）

話すこと

- `get_design_context` がフレームの構造・オートレイアウト・トークン・レイヤー名をまとめて取得する
- 指示に盛り込むのは4つ。リンク、技術スタック、コンポーネント境界、ファイル配置
- 「レイヤー名を反映してほしい」の1行で、3-3の命名が生成物に残る
- まず読むのはファイルツリー。想定と違えばコードを書き出す前に直せる
- 一発で理想どおりにはならない。追加指示で寄せていく作業

見るところ

- 生成結果は人によって違う。講師の画面と一致させるものではないと先に言う
- 指示のURLを差し替え忘れる
- 待ち時間には、Figma側の作り込み（レイヤー名・オートレイアウト・トークン）が生成結果に出る話をする

### 6-3 タスク登録フォームをコード生成する

話すこと

- Figmaのバリアントはコード側のpropsにほぼそのまま対応する。5-2の `variant` がここで効く
- フォーム固有で足すのは2つ。TextFieldとButtonを別ファイルにすること、`variant` をunion型で明示すること
- 頼むのは見た目のコード化まで。イベントハンドラやバリデーションは後から別に指示する

見るところ

- `variant: string` のような緩い型で出たらunion型で書き直させる
- 2画面の見比べで押していたら、3観点のうち色だけでよい
