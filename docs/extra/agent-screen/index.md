# 追加課題3 エージェントに画面を作らせる

2日間はFigmaのデザインを読んでコードにする方向だけをやってきました。ここでは逆に、Figmaに書き込む側をエージェントに任せます。

作るのは3画面目のタスク詳細画面です。ただし**自分ではマウスで一切触りません**。やるのは指示を出すことと、出てきたものを受け取るか差し戻すかを決めることだけです。

## 使う前に

キャンバスでエージェントのプロンプト欄を開きます。見つからないときは、下書きのファイルに複製すると使えることがあります。それでも出てこなければ、プランやシートの都合で使えないので、末尾のClaude Codeでのやり方に進んでください。

エージェントの変更はチャットのUndoか `Cmd + Z`（Windowsは `Ctrl + Z`）で戻せます。作ってきた画面が壊れる心配はしなくてよいので、遠慮なく試してください。

## 受け入れの条件

画面の中身は自分で決めます。何を載せるかは自由ですが、次の3つを満たしていないものは受け取りません。

| 観点 | 見るところ |
| --- | --- |
| 色・余白・角丸 | `tokens` のセマンティックトークン経由になっているか。生のカラーコードや、`purple/500` のようなプリミティブが直接当たっていないか |
| 部品 | `TaskCard`・`PriorityTag`・`Button` などのインスタンスになっているか。似た見た目を一から描き起こしていないか |
| レイヤー名 | 3-3の規約どおりか。`Frame 42` や `Rectangle 5` が残っていないか |

## 演習

### 1. まず素朴に頼む

`タスク詳細画面を作って` だけを送ります。ほかには何も書きません。

出てきたものを見てください。おそらく上の3つは1つも満たしていません。勝手な紫が使われ、既存の `Button` を無視して似たボタンが描き起こされ、レイヤー名は自動名のままです。

### 2. 受け入れ判定をする

上の表の3観点で、1つずつ確認します。色はレイヤーを選んで右サイドバーの塗りを見れば、トークン経由かカラーコード直書きかが分かります。部品はレイヤーパネルのアイコンがひし形かどうかで見分けられます。

差し戻す点を書き出してから、次に進みます。

### 3. 直す指示を出す

見つけた点を1つずつ直させます。ここでプロンプト欄の `@` が使えます。`@` を打つとこのファイルのコンポーネント・バリアブル・スタイルの一覧が出るので、名前で直接指せます。

- `色は @tokens のセマンティックだけを使って`
- `このボタンは @Button のインスタンスに置き換えて`
- `レイヤー名を kebab-case に直して`

### 4. 合格まで繰り返す

3つとも満たすまで往復します。何回かかったか、どの指示が効いてどの指示が効かなかったかを覚えておいてください。

### 5. 最初から通る指示を1本書く

ここが本題です。往復で分かったことを1本の指示文にまとめ直し、**新しいフレームに一度で作らせます**。

1回目と比べてください。1行の指示と、まとめ直した指示の差が、2日間で学んだことです。トークンを使う、状態はバリアントで表す、レイヤー名を整える。人が守るルールとして覚えたことが、そのまま指示に書く内容になります。

## 詰まったときに戻る場所

- トークンの名前と役割 → 4-2
- レイヤー名の規約 → 3-3
- どこまでバリアントにするか → 3-2
- 部品の仕様（サイズ・パディング） → 4-3、6-2

## Claude Codeでやる場合

エージェントが使えないときは、5-1で入れたFigmaプラグインで同じことができます。Claude Codeに「このFigmaファイルにタスク詳細画面を作って」と頼むと、キャンバスに書き込まれます。URLは4章から使っているファイルのものを渡します。

`@` は使えないので、トークン名とコンポーネント名は指示文に書き出します。演習の中身と受け入れの条件は同じです。
