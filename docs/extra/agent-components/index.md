# 追加課題3 エージェントに共通コンポーネントを整備させる

2日間で作ったファイルには、2画面に複製されたままのものや、コンポーネントになっていない部品が残っています。これをエージェントに共通コンポーネントへ整備させます。

**何を共通化するかはエージェントに任せます。**人が判断するのはバリアント設計です。どんなプロパティを持たせ、どんな値を並べるか。ここを決めて伝え、できあがりを確かめるのがこの課題です。

## 使う前に

キャンバスでエージェントのプロンプト欄を開きます。見つからないときは、下書きのファイルに複製すると使えることがあります。それでも出てこなければ、プランやシートの都合で使えないので、末尾のClaude Codeでのやり方に進んでください。

プロンプト欄で `@` を打つと、このファイルのコンポーネント・バリアブル・スタイルの一覧が出ます。名前で直接指せるので、指示に書くときに使えます。

## 1. バックアップを取る

変更はチャットのUndoか `Cmd + Z`（Windowsは `Ctrl + Z`）で戻せますが、何度も往復すると戻しきれなくなります。先にページを複製しておきます。

1. ページ一覧で `task-app` を右クリックして「ページを複製」を選ぶ
2. 複製したページの名前を `task-app-backup` にする
3. 以降は元の `task-app` ページで作業する

## 2. 案を出させる

作らせる前に案だけ出させます。

```text
このページの task-list と task-form で、共通コンポーネントにできるところを
全部挙げてください。
それぞれ、どんなプロパティとバリアントを持たせるかの案も出してください。
まだ作らないでください。
```

何を共通化するかはエージェントの判断でよいので、そのまま受け取ります。

## 3. バリアント設計を判断する

ここが課題の中心です。出てきた案のバリアント設計を、3つの目で見ます。

**プロパティ名と値が規約に沿っているか。** 3-2で作った `state=default/hover`、4章の `priority=high/mid/low`・`active=true/false` と同じ付け方になっているか。`プロパティ1` や `Variant 2` のような自動名が残っていないか。ここはコード生成でpropsの名前になるので、そのまま受け取ると7-1でやったことが台無しになります。

**バリアントの数が増えすぎていないか。** たとえば `sidebar` を共通化するとき、アクティブな項目5つとバッジの有無を1つのプロパティにまとめると10通りになります。プロパティを2つに分ければ5+2で済みます。組み合わせが掛け算で増える設計になっていたら、分けさせます。

**状態と中身の線引きが守られているか。** 3-2で「状態はバリアントで表す」と学びましたが、中身の差はインスタンス側の上書きです。アクティブな項目がどこかは状態ですが、バッジの数字は中身なので、バリアントにするものではありません。数字のパターンごとにバリアントが並んでいたら設計が間違っています。

## 4. 判断を伝えて作らせる

決めたことを条件として渡します。次は書き方の例です。案の中身は人によって違うので、そのまま使うものではありません。

```text
次の方針で共通コンポーネントに整備してください。

- header は1つのコンポーネントにして、両画面をインスタンスに置き換える
- sidebar も1つのコンポーネントにして、アクティブな項目を active プロパティで
  切り替えられるようにする。バッジの表示も同じプロパティで切り替える
- チップ4個を Chip コンポーネントにして、active=true/false のバリアントを持たせる
- アイコンの仮置きは共通化しない。あとで実物に差し替えるので触らないでほしい
- 色・余白・角丸は @tokens のトークンだけを使う
- レイヤー名は kebab-case、コンポーネント名は PascalCase
```

## 5. バリアントで2画面を再現する

作らせたコンポーネントで、元の2画面が再現できるかを確かめます。共通化したものすべてについて、次の2つを見ます。

- **バリアントの切り替えで元の見た目に戻せるか。**`sidebar` を共通化したなら、一覧側のインスタンスでアクティブを `今日` にしてバッジが出るか、フォーム側で `受信箱` にしてバッジが消えるかを確かめます
- **原本を直すと全画面が変わるか。**`header` の原本でアプリ名を書き換えて、両画面が一緒に変わるのを見ます。確認したら戻します

見た目に戻せないならバリアントの設計が足りていません。原本を直しても片方が変わらないなら、インスタンスになっていません。どちらも、何が足りないかを伝えて作り直させます。収まらなくなったら `task-app-backup` から戻してやり直せます。

## 詰まったときに戻る場所

- バリアントの作り方と切り替え方 → 3-2
- 挙がったものが妥当か分からない → 6-1（`sidebar` と `header` をコピーした箇所）、4-4（チップをコンポーネント化しなかった箇所）
- レイヤー名の規約 → 3-3
- トークンの一覧 → 4-2

## Claude Codeでやる場合

エージェントが使えないときは、5-1で入れたFigmaプラグインで同じことができます。Claude Codeに「このFigmaファイルを〜してください」と頼むと、キャンバスに書き込まれます。URLは4章から使っているファイルのものを渡します。

`@` は使えないので、トークン名とコンポーネント名は指示文に書き出します。チャットのUndoもないので、戻すときはFigma側で `Cmd + Z` を押します。
