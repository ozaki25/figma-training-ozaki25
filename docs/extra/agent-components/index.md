# 追加課題3 エージェントに共通コンポーネントを整備させる

2日間で作ったファイルの共通コンポーネントを、エージェントに整備させます。自分では整備せず、できたものを確かめます。

キャンバスでエージェントのプロンプト欄を開きます（開き方は[Figma Learnの案内](https://help.figma.com/hc/en-us/articles/37998629035799-Work-with-the-Figma-agent-in-design-files)）。プランやシートによっては使えないので、出てこなければこの課題は飛ばしてください。プロンプト欄で `@` を打つと、このファイルのコンポーネントやバリアブルを名前で指せます。

## 1. バックアップを取る

何度も往復するとUndoで戻しきれなくなるので、先に複製しておきます。

1. ページ一覧で `task-app` を右クリックして「ページを複製」を選ぶ
2. 複製したページの名前を `task-app-backup` にする
3. 以降は元の `task-app` ページで作業する

## 2. 整備させる

次をそのまま送ります。何を共通化するかはエージェントが決めます。

```text
このページの task-list と task-form を見て、共通コンポーネントにできるところを
整備してください。

- 2画面に複製されている部品は1つのコンポーネントにして、両画面をインスタンスに
  置き換える
- 画面ごとに違うところは、インスタンス側で切り替えられるようにプロパティを作る
- プロパティ名と値の付け方は、既存の priority=high/mid/low や active=true/false に
  そろえる。プロパティ1 のような自動名は残さない
- 性質の違う切り替えは別のプロパティに分けて、組み合わせが掛け算で増えないようにする
- テキストや数字の差はプロパティにしない。インスタンス側の書き換えで表す
- 色・余白・角丸は既存のトークンだけを使う
- コンポーネント名は PascalCase、レイヤー名は kebab-case
- 画面の見た目は変えない
```

## 3. コンポーネントを確かめる

何ができたかは、左サイドバーのアセットパネルで一覧できます。

画面の中のインスタンスを1つずつ選んで、右サイドバーのプロパティを見ます。確かめるのは**元の2画面で使っていた見た目が全部作れるか**です。`Sidebar` なら、アクティブな項目を5つから選べて、バッジの表示も切り替えられる状態が必要です。

足りなければコンポーネントを指して足させます。

```text
@Sidebar に、アクティブな項目を切り替えるプロパティを足してください。
値は受信箱・今日・今週・完了・アーカイブの5つです。
```

プロパティ名が自動名のまま残っていたら、それも直させます。

## 4. 画面を確かめる

2つの画面を開いて元の見た目と比べます。`task-list` はアクティブが `今日` でバッジあり、`task-form` は `受信箱` でバッジなしです。ずれていればプロパティを選び直すか、エージェントに直させます。

最後に `Header` のメインコンポーネント（レイヤーパネルでひし形4つのアイコン）を選び、アプリ名を書き換えて両画面が一緒に変わるかを見ます。変わらなければインスタンスになっていません。確認したら戻します。

## 詰まったときに戻る場所

- バリアントの作り方と切り替え方 → 3-2
- 何が複製されているか → 6-1（`sidebar` と `header` をコピーした箇所）
- コンポーネントになっていない部品 → 4-4（チップ）

## ゴール確認

- [ ] 共通コンポーネントを作らせて、2画面がインスタンスに置き換わった
- [ ] 足りないバリアントを見つけて追加させられた
- [ ] 2画面が元の見た目のまま再現されていることを確認できた
