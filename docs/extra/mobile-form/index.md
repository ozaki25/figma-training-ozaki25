# 追加課題2 スマホ版のタスク登録フォームを設計する

追加課題1が終わったら、2画面目のフォームもスマホ幅で作ります。6章のフォームは560幅のカードを画面の横中央に置く形でしたが、375幅にそのカードは入りません。

この課題も仕様表は渡しません。使えるのは4章のトークンとテキストスタイル、6-2で作った `TextField` と `Button` です。

## 決めること

- 560幅の `form-card` をどうするか。幅を詰めるのか、カードをやめて画面いっぱいに入力欄を置くのか
- 期限と優先度の2列を横に並べたままにするか、縦に積むか
- キャンセルと登録の2ボタンをどう置くか
- ヘッダーとナビをスマホ版の一覧とどうそろえるか

## 満たす条件

- フレームは幅375。高さは内包でよい
- 色・余白・角丸・文字は4章のトークンとテキストスタイルだけを使う。新しい値が必要になったら、`tokens` に追加してから使う
- 幅を375から430に変えても、はみ出しや文字の折り返し崩れが起きない
- ナビとヘッダーがスマホ版の一覧と同じ見た目になっている
- `TextField` と `Button` を使えるところは使う。形が合わないときは、バリアントを足すか別のコンポーネントにするかを選び、どちらにしたか理由を言える
- レイヤー名は3-3の規約どおり

## 演習

### 1. スマホ版の一覧からナビとヘッダーを持ってくる

6-1と同じで、2画面目は1画面目からコピーして始めます。スマホ版の一覧で決めたナビの置き方をそのまま複製し、アクティブの位置だけ付け替えます。

### 2. 入力欄を並べる

`TextField` のインスタンスを5つ置きます。デスクトップ版は560幅のカードの中でしたが、375ではカードの左右パディングを引くと入力欄に残る幅がかなり狭くなります。パディングを何にするか、あるいはカードをやめるかを、実際に置いて幅を見てから決めます。

### 3. 期限と優先度の2列を判断する

デスクトップ版では `field-row` に入れて横2列でした。375で2列にすると1列あたり160幅程度になります。日付の `2026/07/10` と `選択する ▼` が入るかを見て、2列のままにするか縦に積むかを決めます。

### 4. ボタン行を決める

`Button` は幅固定120でした。2つ横に並べると240で、375なら入ります。ただし画面の下端に大きく置く作りもあります。どちらにするか決めて、幅の持ち方（固定か拡大か）を合わせます。

### 5. 幅を変えて崩れを直す

フレームの幅を375から430までドラッグして動かします。入力欄が伸びない、ボタンが片方だけ伸びる、といった崩れは拡大と固定の設定が原因です。2-3に戻って確認してください。

### 6. 4画面を並べる

デスクトップ2画面とスマホ2画面を同じセクションに並べます。同じ部品を使った4画面が、色と文字でそろっているかを確かめます。

### 7. レスポンシブに実装する

追加課題1と同じで、7-1で作ったフォームのコードを1つのコンポーネントに作り直します。7-1の雛形に足すのは次の3点です。

- 2つのフレームのリンクを両方渡し、どちらがスマホ版かを書く
- 出力先は7-1と同じ `src/components/task-form/` にして、いまのコードを置き換えてもらう
- 狭い幅をベースにして、広い幅をブレークポイントで足す形にしてもらう。切り替える幅は一覧とそろえる

`/new/` を開いてブラウザの幅を狭め、期限と優先度の2列やボタン行が、スマホ版のデザインどおりに切り替わるかを見ます。一覧と切り替わる幅がずれていたら、同じ値にそろえてもらいます。

## 詰まったときに戻る場所

- 幅が思ったとおりに伸びない、縮まない → 2-3
- バリアントの仕組みと作り方 → 3-2。足すか別にするかは、デスクトップ版が壊れないか、同じ部品の状態の違いと言えるかで決める
- `TextField` と `Button` の仕様 → 6-2
- トークンの追加のしかた → 4-2
