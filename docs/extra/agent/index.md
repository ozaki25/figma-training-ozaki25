# 追加課題3 エージェントを使ってみる

2日間はFigmaのデザインを読んでコードにする方向だけをやってきました。ここでは逆に、Figmaに書き込む側をエージェントに任せます。

**自分ではマウスで一切触りません。**やるのは指示を出すことと、出てきたものを受け取るか差し戻すかを決めることだけです。

お題は3つあります。上から順に大きくなります。全部やる必要はありません。

## 使う前に

キャンバスでエージェントのプロンプト欄を開きます。見つからないときは、下書きのファイルに複製すると使えることがあります。それでも出てこなければ、プランやシートの都合で使えないので、末尾のClaude Codeでのやり方に進んでください。

プロンプト欄で `@` を打つと、このファイルのコンポーネント・バリアブル・スタイルの一覧が出ます。名前で直接指せるので、`色は @tokens のセマンティックだけを使って` のように書けます。

エージェントの変更はチャットのUndoか `Cmd + Z`（Windowsは `Ctrl + Z`）で戻せます。作ってきた画面が壊れる心配はしなくてよいので、遠慮なく試してください。

## 受け入れの3観点

どのお題でも、出てきたものは次の3つで判定します。1つでも欠けていたら差し戻します。

| 観点 | 見るところ |
| --- | --- |
| 色・余白・角丸 | `tokens` のセマンティックトークン経由か。生のカラーコードや、`purple/500` のようなプリミティブが直接当たっていないか |
| 部品 | `TaskCard`・`PriorityTag`・`Button` などのインスタンスか。似た見た目を一から描き起こしていないか |
| レイヤー名 | 3-3の規約どおりか。`Frame 42` や `Rectangle 5` が残っていないか |

## お題1 練習のカードをトークンに移行させる

`practice` ページのプロフィールカードは、3-1で色スタイルを付けたあと4-1の手順1でそのスタイルを削除したので、いまは生のカラーコードに戻っています。これを4章のトークンとテキストスタイルに移行させます。

実務でデザインシステムを導入したとき、既存の画面をトークンに載せ替える作業と同じです。

```text
practiceページのプロフィールカードの色・余白・角丸を、tokensコレクションの
セマンティックトークンに置き換えてください。文字は4-2で作ったテキストスタイルを当ててください。
```

きれいに移行できない値が混ざっています。カードの白は `surface`、角丸16は `radius/16`、パディング24は `space/24` でぴったり一致しますが、名前の `#333333` と肩書きの `#666666` は近いだけで一致せず、下地フレームの `#E0E0E0` に当たるトークンはありません。

**エージェントはここを勝手に決めます。**近い値に寄せたのか、生の値を残したのか、新しいトークンを足したのかを確認して、自分の方針と違えば差し戻します。「見た目が少し変わってもトークンに寄せる」も「練習用の下地は移行しない」も、どちらも実務で選ばれる判断です。理由が言えれば構いません。

最後に `tokens` の数を数えます。4-2で作ったのは色15個と数値13個です。増えていたらエージェントが自分の判断で足しています。妥当なら残し、そうでなければ消させます。

## お題2 トークンにダークモードを足させる

バリアブルには「モード」という仕組みがあり、1つのトークンに複数の値を持たせて切り替えられます。本編では扱っていない機能です。

```text
tokensコレクションにdarkモードを追加してください。
セマンティックトークンの参照先を、ダーク向けのプリミティブに切り替えてください。
足りないプリミティブは primitives コレクションに追加してください。
```

見るところは1つです。**セマンティックに生の色が直書きされていないか。**プリミティブに暗い色を足して、セマンティックはそれを参照する形になっていれば正しい状態です。4-2で色を2層に分けたのはこのためで、`surface` という名前を変えずに中身だけ差し替わります。

できたら `task-list` を選んでモードを切り替えます。白いカードが暗くなり、文字が反転して読める状態になっていれば成功です。文字が背景に溶けているところがあれば、そのトークンの参照先を直させます。

## お題3 タスク詳細画面を作らせる

3画面目を、指示だけで作らせます。中身は自分で決めます。

まず素朴に `タスク詳細画面を作って` だけを送ってください。ほかには何も書きません。おそらく上の3観点は1つも満たしていません。勝手な紫が使われ、既存の `Button` を無視して似たボタンが描き起こされ、レイヤー名は自動名のままです。

見つけた点を1つずつ直させます。何回かかったか、どの指示が効いてどの指示が効かなかったかを覚えておいてください。

3観点を満たしたら、**往復で分かったことを1本の指示文にまとめ直し、新しいフレームに一度で作らせます。**1回目と比べてください。1行の指示とまとめ直した指示の差が、2日間で学んだことです。トークンを使う、状態はバリアントで表す、レイヤー名を整える。人が守るルールとして覚えたことが、そのまま指示に書く内容になります。

## 詰まったときに戻る場所

- トークンとテキストスタイルの一覧 → 4-2
- レイヤー名の規約 → 3-3
- どこまでバリアントにするか → 3-2
- 部品の仕様（サイズ・パディング） → 4-3、6-2

## Claude Codeでやる場合

エージェントが使えないときは、5-1で入れたFigmaプラグインで同じことができます。Claude Codeに「このFigmaファイルに〜してください」と頼むと、キャンバスに書き込まれます。URLは4章から使っているファイルのものを渡します。

`@` は使えないので、トークン名とコンポーネント名は指示文に書き出します。お題と受け入れの3観点は同じです。
