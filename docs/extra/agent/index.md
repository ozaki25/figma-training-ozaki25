# 追加課題3 エージェントを使ってみる

2日間はFigmaのデザインを読んでコードにする方向だけをやってきました。ここでは逆に、Figmaに書き込む側をエージェントに任せます。

**自分ではマウスで一切触りません。**やるのは指示を出すことと、出てきたものを受け取るか差し戻すかを決めることだけです。

お題は2つあります。片方だけでも構いません。

## 使う前に

キャンバスでエージェントのプロンプト欄を開きます。見つからないときは、下書きのファイルに複製すると使えることがあります。それでも出てこなければ、プランやシートの都合で使えないので、末尾のClaude Codeでのやり方に進んでください。

プロンプト欄で `@` を打つと、このファイルのコンポーネント・バリアブル・スタイルの一覧が出ます。名前で直接指せるので、`色は @tokens のセマンティックだけを使って` のように書けます。

エージェントの変更はチャットのUndoか `Cmd + Z`（Windowsは `Ctrl + Z`）で戻せます。作ってきた画面が壊れる心配はしなくてよいので、遠慮なく試してください。

## お題1 共通コンポーネントを整備させる

2日間で作ったファイルには、コンポーネントになっていない部品と、2画面に複製されたままのものが残っています。どこがそうなっているかを見つけるところも含めて、エージェントに任せます。

```text
このファイルで共通コンポーネントにできていないところを見つけて、
共通コンポーネントに整備してください。
画面ごとに違うところはバリアントで表してください。
```

出てきた結果を見て決めるのは1つです。**共通化の切り方が自分の考えと合っているか。**何を1つの部品にまとめたか、どこをバリアントにしたか、共通化すべきでないものまでまとめていないか。

判断の尺度は「変更が1か所で済むか」です。片方の画面を直したときに、もう片方も一緒に変わる状態になっていれば共通化できています。

違えばUndoで戻して、条件を足して投げ直します。最後に2画面を開いて、見た目が保たれているかを見ます。

## お題2 タスク詳細画面を作らせる

3画面目を、指示だけで作らせます。何を載せるかは自分で決めます。

まず `タスク詳細画面を作って` だけを送ってください。ほかには何も書きません。おそらく勝手な紫が使われ、既存の `Button` を無視して似たボタンが描き起こされ、レイヤー名は自動名のままです。

見つけた点を条件にして投げ直します。ここで `@` が効きます。

- `色は @tokens のセマンティックだけを使って`
- `このボタンは @Button のインスタンスに置き換えて`
- `レイヤー名を kebab-case に直して`

満足できる状態になったら、**往復で分かったことを1本の指示文にまとめ直し、新しいフレームに一度で作らせます。**1回目と比べてください。1行の指示とまとめ直した指示の差が、2日間で学んだことです。トークンを使う、状態はバリアントで表す、レイヤー名を整える。人が守るルールとして覚えたことが、そのまま指示に書く内容になります。

## 詰まったときに戻る場所

- トークンとテキストスタイルの一覧 → 4-2
- レイヤー名の規約 → 3-3
- どこまでバリアントにするか → 3-2
- 部品の仕様（サイズ・パディング） → 4-3、6-2

## Claude Codeでやる場合

エージェントが使えないときは、5-1で入れたFigmaプラグインで同じことができます。Claude Codeに「このFigmaファイルに〜してください」と頼むと、キャンバスに書き込まれます。URLは4章から使っているファイルのものを渡します。

`@` は使えないので、トークン名とコンポーネント名は指示文に書き出します。お題の中身は同じです。
