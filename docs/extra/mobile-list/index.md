# 追加課題: スマホ版のタスク一覧を設計する

4章から7章までを終えたあとの課題です。4章で作ったタスク一覧はデスクトップの1440幅でした。同じタスク一覧を、スマホの幅で作り直します。

これまでのレッスンと違って、仕様表は渡しません。何をどこに置くかは自分で決めます。使えるのは4章で定義したトークン・テキストスタイル・コンポーネントです。想定は60分から90分です。

## 決めること

375幅にサイドバーは入りません。TaskCardに6つ並んでいた要素も横一列には収まりません。次の4つを自分で決めるのが、この課題の中身です。

- サイドバーの5項目をどこに置くか
- TaskCardの6要素（チェック・優先度・タイトルと説明・カテゴリ・担当・期限）のうち、何を残して何を縦に積むか
- 統計カード3枚をどう見せるか
- フィルタのチップ4個をどう収めるか

## 満たす条件

自分の成果物が課題を満たしているかは、次の5つで判定できます。

- フレームは幅375。高さは内包でよい
- 色・余白・角丸・文字は4章のトークンとテキストスタイルだけを使う。新しい値が必要になったら、`tokens` に追加してから使う
- 幅を375から430に変えても、はみ出しや文字の折り返し崩れが起きない
- 既存のコンポーネントを使えるところは使う。形が合わないときは、バリアントを足すか別のコンポーネントにするかを選び、どちらにしたか理由を言える
- レイヤー名は3-3の規約どおり

## 演習

### 1. 骨組みを作る

デスクトップ版と同じ手順で、外側から作ります。幅375のフレームを作り、中を縦に分けて、それぞれの高さの持ち方（固定か内包か拡大か）を決めます。

デスクトップ版の `sidebar` と `header` はそのままでは入りません。ナビをどこに持っていくかを、ここで決めます。

### 2. TaskCardのスマホ版を作る

375幅に6要素を横一列で置くと、タイトルが数文字で折り返します。まず横一列のまま置いてみて、何が入らないかを目で見てから決めてください。

デスクトップ版の `TaskCard` を作り替えるのではなく、複製して別の名前にするか、バリアントを足すかを選びます。デスクトップ版が壊れないようにするのが条件です。

### 3. 統計とフィルタを収める

`StatCard` 3枚は、横に並べると1枚が115幅程度になります。数値が28pxなので、そのままでは窮屈です。並べ方を変えるか、見せる情報を減らすかを決めます。

チップ4個も横一列では収まりません。オートレイアウトの折り返し（ラップ）を使う手もあります。

### 4. 幅を変えて崩れを直す

フレームの幅を375から430までドラッグして動かします。崩れる箇所は、たいてい固定にすべきところを拡大にしているか、その逆です。2-3に戻って確認してください。

### 5. デスクトップ版と並べる

6-3でやったように、デスクトップ版の2画面と同じセクションに入れて並べます。3画面を並べて、色と文字が同じ見た目になっているかを確かめます。

### 6. コードにする

ここまでできたら、5-2と同じ流れでコードにできます。指示の雛形も5-2のものがそのまま使えます。スマホ版で足したトークンがあれば、`@theme` に追記してから生成します。

## 詰まったときに戻る場所

- 幅が思ったとおりに伸びない、縮まない → 2-3
- バリアントを足すか別コンポーネントにするか迷う → 3-2
- レイヤー名の付け方 → 3-3
- トークンの追加のしかた → 4-2
