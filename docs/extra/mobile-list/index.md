# 追加課題1 スマホ版のタスク一覧を設計する

4章から7章までを終えたあとの課題です。4章で作ったタスク一覧はデスクトップの1440幅でした。同じタスク一覧を、スマホの幅で作り直します。

これまでのレッスンと違って、仕様表は渡しません。何をどこに置くかは自分で決めます。使えるのは4章で定義したトークン・テキストスタイル・コンポーネントです。

## 決めること

375幅にサイドバーは入りません。TaskCardに6つ並んでいた要素も横一列には収まりません。自分で決めるのは次のところです。

- サイドバーの5項目をどこに置くか
- サイドバーにあったロゴとアカウント表示、上部のヘッダーをどうするか
- TaskCardの6要素（チェック・優先度・タイトルと説明・カテゴリ・担当・期限）のうち、何を残して何を縦に積むか
- 統計カード3枚をどう見せるか
- フィルタのチップ4個をどう収めるか

## 満たす条件

- フレームは幅375。高さは内包でよい
- 色・余白・角丸・文字は4章のトークンとテキストスタイルだけを使う。新しい値が必要になったら、`tokens` に追加してから使う
- 幅を375から430に変えても、はみ出しや文字の折り返し崩れが起きない
- 既存のコンポーネントを使えるところは使う。形が合わないときは、バリアントを足すか別のコンポーネントにするかを選び、どちらにしたか理由を言える
- レイヤー名は3-3の規約どおり

## 演習

### 1. 骨組みを作る

デスクトップ版と同じ手順で、外側から作ります。幅375のフレームを作り、中を縦に分けて、それぞれの高さの持ち方（固定か内包か拡大か）を決めます。

デスクトップ版の `sidebar` と `header` はそのままでは入りません。ナビとヘッダーをどこに持っていくかを、ここで決めます。ロゴとアカウント表示の行き先も一緒に決めます。

### 2. TaskCardのスマホ版を作る

375幅に6要素を横一列で置くと、タイトルが数文字で折り返します。まず横一列のまま置いてみて、何が入らないかを目で見てから決めてください。

デスクトップ版の `TaskCard` を作り替えるのではなく、複製して別の名前にするか、バリアントを足すかを選びます。デスクトップ版が壊れないようにするのが条件です。

### 3. 統計とフィルタを収める

`StatCard` 3枚を横に並べると、375から間隔と画面の左右パディングを引いて3で割るので、1枚が100から115程度になります。数値が28pxなので、そのままでは窮屈です。並べ方を変えるか、見せる情報を減らすかを決めます。

チップ4個も横一列では収まりません。横スクロールにする手も、オートレイアウトを折り返しにする手もあります（右サイドバーのオートレイアウトで、方向を折り返しに変えられます）。

### 4. 幅を変えて崩れを直す

フレームの幅を375から430までドラッグして動かします。崩れる箇所は、たいてい固定にすべきところを拡大にしているか、その逆です。2-3に戻って確認してください。

### 5. デスクトップ版と並べる

6-3でやったように、デスクトップ版の2画面と同じセクションに入れて並べます。3画面を並べて、色と文字が同じ見た目になっているかを確かめます。

### 6. レスポンシブに実装する

5-2で作った一覧のコードを、デスクトップ版とスマホ版の2つのデザインから1つのコンポーネントに作り直します。Figmaにブレークポイントの概念はないので、どの幅で切り替えるかはコード側で決めます。ここが今回の課題で新しいところです。

5-2の雛形に足すのは次の3点です。

- 2つのフレームのリンクを両方渡し、どちらがスマホ版かを書く
- 出力先は5-2と同じ `src/components/task-list/` にして、いまのコードを置き換えてもらう
- 狭い幅をベースにして、広い幅をTailwindのブレークポイント（`sm:`・`md:`・`lg:` など）で足す形にしてもらう

書き出せたら、ブラウザの幅をドラッグで狭めます。スマホ版のデザインに切り替わり、途中でどちらとも違う崩れた状態にならないかを見ます。切り替わる幅が気に入らなければ、ブレークポイントを変えてもらいます。

## 詰まったときに戻る場所

- 幅が思ったとおりに伸びない、縮まない → 2-3
- バリアントの仕組みと作り方 → 3-2。足すか別にするかは、デスクトップ版が壊れないか、同じ部品の状態の違いと言えるかで決める
- レイヤー名の付け方 → 3-3
- トークンの追加のしかた → 4-2
