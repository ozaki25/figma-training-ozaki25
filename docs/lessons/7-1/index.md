# 7-1 2日間のふりかえり

タスク管理ツールの2画面（一覧と登録フォーム）を、ゼロからデザインし、Figma MCPでコードに変換するところまで進めました。ここでは2日間で通ったルートと身についたことを短く整理し、次に何を試すとよいかを添えます。

## 2日間で通ったルート

![Day1で1〜3章、Day2で4〜6章を進めた流れの俯瞰図。1〜3章の練習で覚えた手順を4〜5章の本番に当てはめ、6章でコード生成につなぐ積み上がりを示す](/lessons/7-1/two-day-overview.svg)

各章でやったことを一言でまとめると次のとおりです。

- [1章 Figmaを開いてみる](/lessons/1-1/): 画面構成、フレームの作成、ズーム・パンといった基本操作
- [2章 基本要素を作る](/lessons/2-1/): シェイプ・文字の配置、オートレイアウト、内包/拡大/固定の3つのリサイズ挙動
- [3章 デザインの基礎知識](/lessons/3-1/): 色とテキストのスタイル化、コンポーネントとバリアント、コード生成を見据えた命名、バリアブルによるデザイントークン管理
- [4章 タスク一覧画面を作る](/lessons/4-1/): 骨組み、デザイントークンの定義、TaskCardと優先度バリアント、一覧画面の仕上げ
- [5章 タスク登録フォームを作る](/lessons/5-1/): フォームの骨組み、TextFieldとButtonのコンポーネント化、2画面の見た目の統一
- [6章 Figma MCP + Claude Codeでコード化](/lessons/6-1/): MCPのセットアップ、一覧とフォームをそれぞれコードに変換

1〜3章は同じサンプル（プロフィールカード）で手順だけを身につけ、4〜5章で本番の2画面をゼロから作り直す構成でした。3-3で決めたレイヤー命名や4-2で定義したトークンが、6章のコード生成の品質にそのまま効いた実感が持てたはずです。

## 身についたことの確認

- [ ] Figmaでフレーム・オートレイアウト・内包/拡大/固定を使い、実装しやすい構造でUIを組める
- [ ] 色・テキストのスタイル化とコンポーネント/バリアントを使い、部品を再利用可能な形に切り出せる
- [ ] Figma MCP + Claude Codeに対して、URL・スタック・分割・命名反映を含む指示を出してコードに変換できる

3つのどれかにひっかかるなら、対応する章のレッスンをもう一度手を動かして通すとよいです。

## このハンズオンでは扱わなかったこと

範囲を絞るため、次のトピックは意図的に外しました。実務ではよく出会うので、必要になった時点で個別に調べると効率が良いです。

- **プロトタイピング**: 画面遷移リンク（Prototypeタブ）でクリックやアニメーションを付ける。動く画面のデモを共有したいときに使う
- **バリアブルのモード切り替え**: 1つのトークンにライト用・ダーク用の値を持たせて一括で切り替える機能。4-2で作った `tokens` コレクションの続きとして、値の枠を増やすと実現できる（プランによっては枠を増やせない）
- **チーム作業**: Team Libraryで別ファイルからスタイル・コンポーネントを共有する、Branchingで並行編集する、といったチーム運用の仕組み
- **本格的な実装への接続**: フォームライブラリ（React Hook Formなど）、状態管理、APIとの結線、バリデーション。6章で生成したコードは見た目まで
- **別のスタックでのコード生成**: 今回はReact + Tailwindを標準にしましたが、Vue、React Native、素のHTML/CSSでも同じFigmaファイルから生成できます。指示文のスタック指定を変えるだけで試せます

## 明日から使うためのヒント

- 既存のUIを見て「オートレイアウトならどう組むか」を頭の中でなぞる癖を付けると、実装時のマークアップの当たりが早くなる
- 自分のプロジェクトで、まずヘッダーやカード1つでよいのでFigmaに起こしてMCPでコード生成にかけてみる。1画面まるごとより、部品単位で始めるほうが指示のコツがつかみやすい
- 生成コードは「たたき台」として扱う。命名・型・分割を後から整えるつもりでいると、指示も気楽に書けるようになる
