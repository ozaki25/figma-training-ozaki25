# 3-4 バリアブルでデザイントークンを管理する

3-1で色と文字をスタイルにまとめました。実務のチーム開発では、その一歩先に「デザイントークン」という考え方があります。色・余白・角丸などデザイン上の決定を、名前付きの値として一元管理する仕組みです。CSSのカスタムプロパティ（`--color-brand`）やTailwindのテーマ設定と同じ発想で、Figmaでは**バリアブル**（Variables）という機能が担当します。

このレッスンでは、3-1〜3-3で仕上げたプロフィールカードを使って、トークンを作り、適用し、一括で変わるところまでを体験します。

## スタイルとバリアブルの使い分け

| | 中身 | 向いているもの |
| --- | --- | --- |
| スタイル | 複数プロパティの束 | テキストスタイル（フォント+サイズ+ウェイト）のようなセット |
| バリアブル | 単一の値 | `#7C3AED` や `24` という値そのものに名前を付けたいとき |

実務では、バリアブルで値を管理し、要素やスタイルからその値を参照する、という層構造にすることが多いです。この教材の4章以降の本番はスタイルで統一しますが、値の管理をチームで厳密にやりたくなったときに効いてくるのがバリアブルです。

## トークンの2層構造

デザイントークンは、2つの層に分けて名前を付けるのが定石です。

- **プリミティブトークン**: `purple/500` = `#7C3AED` のように、値に機械的な名前を付けたもの
- **セマンティックトークン**: `brand` = `purple/500` への参照（エイリアス）。「何に使う値か」を表す

CSSでいうと `--purple-500: #7C3AED;` と `--color-brand: var(--purple-500);` の関係です。紫を微調整したいときはプリミティブの値を1か所直すだけ、ブランドカラーを別の色系統に切り替えたいときはエイリアスの参照先を差し替えるだけで済みます。

## 演習: カードの色をトークン化する

3-1でスタイル化したカードを使います。

### 1. バリアブルパネルを開く

1. 画面左端のナビゲーションバーから「バリアブル」を開く。まだ何も作っていなければ「このファイルにはバリアブルが作成されていません」と表示される

### 2. プリミティブトークンを作る

1. 「+ 作成」を押し、種類の一覧から「色」を選ぶ。バリアブルの入れ物（コレクション1）が自動で作られ、名前が入力できる状態の色バリアブルが1行できる（コレクション名はそのままでよい）
2. 名前に `purple/500` と入力し、値を `#7C3AED` に変える
3. 同じように色のバリアブルをあと2つ追加し、`gray/700` = `#333333`、`gray/400` = `#777777` にする。名前に `/` を入れると、スタイルと同じようにグループ化される

### 3. セマンティックトークンを作る

1. カラーのバリアブル `brand` を追加する
2. `brand` の値の欄を右クリックし、「エイリアスを作成」を選んで `purple/500` を参照する。値がカラーコードではなくトークン名の参照になる

### 4. カードに適用する

1. カードの正円を選択し、「塗り」の4点アイコン（スタイルとバリアブルを適用）を開く。アバターを画像にしている場合は、適用すると画像が置き換わってしまうので、キャンバスの空いた場所に四角形を描いて、それを対象にする（伝播の確認が終わったら消してよい）
2. パネルには、バリアブル（四角いチップ）と、「スタイル」見出しの下に3-1で登録した色スタイル（丸いチップ）が並ぶ。3-1のスタイルにも `brand` と名付けたので同名が2つ見えるが、ここでは**四角いチップ**（バリアブル）の `brand` を選ぶ
3. 塗りの表示がバリアブル名の `brand` に変わる

### 5. 伝播を確認する

1. バリアブルパネルで `purple/500` の値を緑（例: `#0ACF83`）に変える
2. `brand` を経由して、正円（画像にした場合は演習4の四角形）の色が変わるのを確認する
3. 確認できたら `#7C3AED` に戻す

正円そのものは一度も触っていないのに、プリミティブの値1つで見た目が変わりました。トークンが増えても管理する場所は1つ、という状態がデザイントークン管理の目指すところです。

バリアブルには、1つの名前にライト用・ダーク用など複数の値を持たせて一括で切り替える「モード」という機能もあります。ダークモード対応やブランドの切り替えは、この値の枠を増やす仕組みで実現します。

::: warning 操作できない項目があったら
バリアブルの値の枠を増やす操作（モードの追加）など、一部の機能はプランによって使えないことがあります。アップグレードを勧めるダイアログが出たら、機能がそのプランの範囲外だったということなので、右上の×で閉じて先へ進んでください。このレッスンの演習の手順は、プランに関係なく実施できます。
:::

## コード生成との関係

6章で使うFigma MCPには、ファイルのバリアブル一覧を取得する仕組みがあります。トークン名がそのまま生成コードのCSS変数名やTailwindテーマの種になるので、ここでも「良い名前を付けること」が品質に直結します。3-3のレイヤー名と同じ理屈です。
