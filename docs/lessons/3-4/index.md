# 3-4 バリアブルでデザイントークンを管理する

3-1で色と文字をスタイルにまとめました。実務のチーム開発では、その一歩先に「デザイントークン」という考え方があります。色・余白・角丸などデザイン上の決定を、名前付きの値として一元管理する仕組みです。CSSのカスタムプロパティ（`--color-brand`）やTailwindのテーマ設定と同じ発想で、Figmaでは**バリアブル**（Variables）という機能が担当します。

このレッスンでは、3-1〜3-3で仕上げたプロフィールカードを使って、トークンを作り、適用し、一括で変わるところまでを体験します。

## スタイルとバリアブルの使い分け

| | 中身 | 向いているもの |
| --- | --- | --- |
| スタイル | 複数プロパティの束 | テキストスタイル（フォント+サイズ+ウェイト）のようなセット |
| バリアブル | 単一の値 | `#7C3AED` や `24` という値そのものに名前を付けたいとき |

実務では、バリアブルで値を管理し、要素やスタイルからその値を参照する、という層構造にすることが多いです。この教材の4章以降の本番はスタイルで統一しますが、値の管理をチームで厳密にやりたくなったときに効いてくるのがバリアブルです。

## トークンの2層構造

デザイントークンは、2つの層に分けて名前を付けるのが定石です。

- **プリミティブトークン**: `purple/500` = `#7C3AED` のように、値に機械的な名前を付けたもの
- **セマンティックトークン**: `brand` = `purple/500` への参照（エイリアス）。「何に使う値か」を表す

CSSでいうと `--purple-500: #7C3AED;` と `--color-brand: var(--purple-500);` の関係です。紫を微調整したいときはプリミティブの値を1か所直すだけ、ブランドカラーを別の色系統に切り替えたいときはエイリアスの参照先を差し替えるだけで済みます。

## 演習: カードの色をトークン化する

3-1でスタイル化したカードを使います。

### 1. バリアブルパネルを開く

1. 画面左端のナビゲーションバーから「バリアブル」を開く
2. 初回はコレクション（トークンの入れ物）を作る。名前を `tokens` にする

### 2. プリミティブトークンを作る

1. カラーのバリアブルを3つ作り、3-1で使った色を登録する: `purple/500` = `#7C3AED`、`gray/700` = `#333333`、`gray/400` = `#777777`
2. 名前に `/` を入れると、スタイルと同じようにグループ化される

### 3. セマンティックトークンを作る

1. カラーのバリアブル `brand` を追加する
2. `brand` の値の欄を右クリックし、エイリアスの作成から `purple/500` を選ぶ。値がコードではなくトークン名の参照になる

### 4. カードに適用する

1. カードの正円を選択し、「塗り」の4点アイコン（スタイルとバリアブルを適用）を開く
2. 一覧から `brand` を選ぶ。塗りの表示がバリアブル名に変わる

### 5. 伝播を確認する

1. バリアブルパネルで `purple/500` の値を緑（例: `#0ACF83`）に変える
2. `brand` を経由して、正円の色が変わるのを確認する
3. 確認できたら `#7C3AED` に戻す

正円そのものは一度も触っていないのに、プリミティブの値1つで見た目が変わりました。トークンが増えても管理する場所は1つ、という状態がデザイントークン管理の目指すところです。

## モードは有料プランの機能

バリアブルの代表的な使い方に「モード切り替え」があります。同じ `brand` という名前に、ライトモード用とダークモード用の2つの値を持たせて一括で切り替える仕組みです。モードの追加は有料プランの機能なので、このハンズオンでは仕組みの紹介にとどめます。

## コード生成との関係

6章で使うFigma MCPには、ファイルのバリアブル一覧を取得する仕組みがあります。トークン名がそのまま生成コードのCSS変数名やTailwindテーマの種になるので、ここでも「良い名前を付けること」が品質に直結します。3-3のレイヤー名と同じ理屈です。
