# レッスンレビュースキル

指定されたレッスンを、下記チェックリストの**全カテゴリ**で必ずレビューします。
場当たりに気づいた点だけ直すのは禁止。**毎回チェックリストを頭から最後まで通す**こと。

## 基準は CLAUDE.md

このチェックリストは運用の補助です。**品質の基準は `CLAUDE.md` の「執筆ルール」「自然な日本語で書く」セクション全体**です。

- レビュー開始時に、**毎回 `CLAUDE.md` を最初から最後まで読む**こと。記憶や下のチェックリストだけに頼らない
- チェックリストに載っていない方針が CLAUDE.md にあれば、それも必ず適用する（CLAUDE.md が優先）
- CLAUDE.md の方針が更新されたら、このスキルのチェックリストにも反映する
- 併せて `NOTES.md` に該当章の追加調査があれば読んでから始める（Figma UIの現行仕様の確認）

## 引数

- `$ARGUMENTS` にレビュー対象（`1-1`、`docs/lessons/2-2/index.md` など）
- 複数指定された場合は1本ずつ順にループを回す

## レビューのループ（仕組み）

1本のレッスンについて、次を**指摘ゼロになるまで繰り返す**:

```
① 対象ファイル（docs/lessons/<章>-<節>/index.md）を最初から最後まで通読する
② 下のチェックリストを A→I の順に全項目チェックし、指摘を箇条書きで列挙する
③ 指摘を修正する
④ npm run docs:build と npm run docs:lint が両方通ることを確認する
⑤ ②に戻る。指摘が出なくなったら、その時点で1周「指摘なし」を確認して終了
```

**1周でもチェックを飛ばさない。** 修正で別の問題を作ることがあるため、修正後は必ず全項目を再チェックする。

最後に、各カテゴリについて「指摘なし / 指摘あり（内容と対応）」を表で報告する。

## チェックリスト

### A. Figma UI・仕組みの正確性・最新版（最優先）

- 扱う Figma の UI・メニュー名・ショートカット・機能を、**執筆時点（2026年7月）の現行 UI3** として書いているか。訓練データの記憶だけで書かない
- 古いメニュー配置・旧名称（例: 上部ツールバー時代の記述、旧 Auto Layout パネル）を「現行」として説明していないか
- ロールアウト中の機能（新ナビゲーションバー等）は、新旧どちらの UI にも当たり得ることを踏まえた書き方になっているか
- Figma MCP（6章）は特に変化が速い。セットアップ手順・プラン制約が古くないか
- `NOTES.md` の「Figma現行UI調査」および該当章の追加調査と整合しているか。矛盾があれば `NOTES.md` を更新したか
- 同じ機能を扱う他レッスンと矛盾していないか

### B. 構成・設計

- **単一の核（1テーマ）**になっているか。複数の核が混在して 1 本に詰め込まれていないか
- **15 分で読み切れるボリューム**か。網羅性より「今日はこれだけ覚えれば OK」を優先しているか
- 仕組み・背景から語っているか。表面的な紹介で終わらず、なぜそれが必要か・どう動くかから説明しているか
- **レッスン単体で完結**しているか。「前のレッスンで学んだ〜」など他レッスンへの参照に頼っていないか。必要ならその場で簡潔に補っているか
- **演習を中心に構成**されているか（読むだけで終わらせず、実際に Figma を操作するステップがあるか）
- **末尾に「ゴール確認」チェックポイントがあり、自分で確認できる形**になっているか
- ドリル・クイズ・小テストを作っていないか（この教材では作らない方針）

### C. ゴール・まとめ

- 「ゴール確認」やまとめが **3 項目程度（多くても 4）**か
- 各項目が **1 行・1 文以内**の短いフレーズか。本文の説明を書き込んでいないか
- 本文の繰り返しになっていないか
- 項目が多いとき、分割ではなく統合で減らしているか

### D. 文章品質（直訳調・AI 詩的文体）

- 直訳調: 名詞化の硬さ（「〜の欠如」など）、不自然な受動態（「提供されています」）、回りくどい修飾がないか
- 英語由来のラベル語（「落とし穴」「柱」「層」）を見出し・番号ラベルに裸で使っていないか
- **カタカナ専門用語の安易な採用**がないか。前文で平易に言い換えた直後に、急にカタカナ・漢語へ切り替えていないか
- AI 詩的文体: 体言止めの列挙、短文の連打、問いかけ + 即答、ドラマチックな一文で締める、がないか
- **「説明の足場」が残っていないか**（CLAUDE.md 参照）。メタな前置き（「まず全体像を押さえると」）／数え上げ宣言（「違いは大きく N つです」）／教科書的な締め（「〜が重要です」）／不自然な比喩を削り、中身だけ残す
- **ダッシュ（——）を文中に使っていないか**。文を分けるか、カッコを使う
- **括弧書き・記号（＝・＋）を多用していないか**。装飾的な「（…）」は文に溶かす。「A＝B」は「A は B」と言葉で書く
- 3 文以上続く段落を、短文・箇条書き・表に分解しているか
- **同僚に口頭で説明するとき、その言い回しを使うか**で各段落を判定する。使わない言い回しは削る

### E. 見出し

- 名詞句で簡潔か。詩的・文学的な語（正体／裏側／魔法／旅／扉／真実／鍵／秘密）を使っていないか
- レッスンのタイトルは PLAN.md の章立て名（「Figma を開いてみる」等の動詞形も可）に従っているか
- 本文中の節見出しは名詞句を基本にしているか

### F. ペルソナ

- 読者（**Figma 未経験のエンジニア**）が共感できるか
- **Figma の知識を一切前提にしていないか**。「〜は知っての通り」「〜はご存じの」といった前提を置いていないか
- HTML/CSS の知識は前提にしてよい。CSS への読み替え（例: Fill container ≒ `flex: 1`）で理解を助ける書き方になっているか
- 専門用語を初出時に平易な言葉で説明しているか

### G. 演習・図版・アセット

- **演習手順が具体的**か。「四角形ツールを選ぶ（ショートカット `R`）」のように操作を再現できる粒度で書かれているか
- 図版・完成イメージは Figma MCP で作成した実キャプチャか、SVG 自作か（`docs/public/lessons/<章>-<節>/` 配下、絶対パス参照）。ASCII アートを使っていないか
- **概念図で Mermaid を使っていないか**（この教材では禁止。SVG 自作のみ）
- 演習の答え（`.fig` ファイル）を配布していないか（画像のみ許可）
- 画像に `alt` テキストが付いており、内容が伝わるか

### H. 図・色・可読性

- **図が色だけで区別していないか**。意味の区別は形・記号・パターン・位置・ラベルなど色以外の手がかりを併用する。グレースケールにしても読めるかで判定する
- SVG のテキスト・線色が**ライト/ダーク両方で見えるか**（`currentColor` 利用や両モードで通るコントラストの確認）
- カラーコントラストが WCAG AA を満たしているか（ボディテキスト 4.5:1、大見出し 3:1）
- 表・長いコードブロックが横スクロールで破綻していないか

### I. ビルド・lint・描画

- `npm run docs:build` が通るか
- `npm run docs:lint`（textlint）が通るか。ルール違反は本文修正で対応し、`textlint-disable` の乱用で消さない
- **太字 `**` が素通りしていないか**。markdown-it は全角約物（（）「」など）に隣接した `**` を太字にしないため、目視では気づけない。対象ファイルを `.claude/hooks/check-bold.cjs` に流し（`cat docs/lessons/<章>-<節>/index.md | node .claude/hooks/check-bold.cjs`）、出力が空であることを確認する。崩れたら約物を `**` の外に出す（例: `**目次（一覧）**` → `**目次**（一覧）`）
- 画像の絶対パス（`/lessons/<章>-<節>/xxx.svg`）が実ファイルと一致しているか
